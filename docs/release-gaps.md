# Release gap audit — strict one-binary product

Audit date: 2026-09-29. This is a **moving source audit**, not a claim about a shipped release. `P0` means the hard user contract cannot yet be met; `P1` means substantial verification or integration remains. Owners and decisive experiments are included so a gap can be closed by evidence. Target architecture: [architecture.md](architecture.md); incremental migration: [incremental-plan.md](incremental-plan.md); local-path/theme contracts: [configuration.md](configuration.md), [themes.md](themes.md).

## What is already established

`Mote.Engine` has immutable UTF-16 rope snapshots, CR/LF/CRLF indexing, bounded history, ordered `Changed` events, strict encoding and SHA-256-guarded same-path Save. Explicit overwrite of an existing different target requires `FileOverwriteToken`; ordinary Save As refuses silent replacement ([review and regression evidence](code-review.md)). All six format policies expose structural semantic results; Plain text, CSV and Markdown also have per-document incremental sessions. `Mote.Configuration` resolves default `~/.mote/{config.toml,cache,data,traces}` with `MOTE_HOME` and config overrides; `Mote.Themes` statically registers dark, light and high-contrast policies with contrast tests. The native shell asks the OS for `PrefersDark`, uses app-level Save As confirmation, and projects format-aware, source-mapped preview spans; Windows styling is debounced into a one-pass update. Telemetry defaults to `~/.mote/traces` when opted in, has a bounded nonblocking JSONL sink, and does not accept path/content fields.

**Single-binary milestone achieved, not full-product validation:** Integrated hosted [CI run 36542765032](https://github.com/kleedaisuki/mote/actions/runs/36542765032) passed all six jobs: Windows/macOS solution tests plus Native AOT `Mote.Native` on win-x64, win-arm64, osx-x64 and osx-arm64. Its strict inventory gate accepted **one release executable and zero sidecars** for each RID; runtime and native GUI startup/Launch Services smoke passed. Reported binary sizes are 5.21/5.31/12.14/11.87 MB in that RID order (inventory artifacts are attached to the run). This closes the former P0 *feasibility/integration* binary-count gap. It does **not** exercise real open→edit→save/reopen, IME, screen readers, large-file interactions, macOS signing/notarization, or paint latency.

## Active gates

| Priority | Code/evidence and impact | Owner + decisive experiment | Exit condition |
| --- | --- | --- | --- |
| **P0 — full semantic editing on large files is not yet delivered** | `PlainTextPolicy`, `CsvPolicy`, and `MarkdownPolicy` now have per-document `IFormatSession` implementations; Markdown's fast path deliberately limits reuse to isolated simple blocks and falls back safely. `JsonPolicy`, `TomlPolicy`, and `YamlPolicy` remain legacy `Analyze(string)` implementations. Crucially, `NativeEditorController.ScheduleAnalysis` still calls `policy.Analyze(text)` rather than any session, fully analyzes only snapshots ≤2 Mi UTF-16 units, samples a bounded page for Markdown/CSV/plain, and **defers all semantic analysis** for large JSON/TOML/YAML. The incremental contract is not yet integrated in the product. | **Formats + Native desktop.** Wire versioned sessions from `Document.Changed` through the native controller; compare each session against fresh full parses. On a >2 MiB JSON/TOML/YAML file, place an offscreen error and request complete analysis; record coverage/progress, memory and cancellation. | UI exposes exact version and `Provisional`/`CoveredRegion`/`Complete`; no false “valid” state; all formats can eventually produce full semantics in a bounded/cancelable workflow, with measured reuse where claimed. |
| **P0 — native large-file view still has page-local editor semantics** | `NativeEditorController` targets a 64 Ki-unit page, allowing up to 8 Ki units of edit slack before rebasing; its status explicitly says “whole-document selection unavailable.” `INativeEditorShell.TextChanged` supplies complete page text after an edit. This avoids a second whole-file control buffer but means Ctrl+A, drag selection, copy/search and caret movement cannot span the document. | **Native desktop + large-file UI/perf.** Open a 100 MiB file with a marker crossing a 64 Ki boundary; exercise select-all/copy, shift-selection, search, replace, undo and navigation across the boundary on both OSes. Measure per-key edit allocation from whole-page read/diff. | One coherent document-level selection/navigation/edit contract for all sizes; if native controls cannot provide it behind a bounded projection, use a single engine-backed virtual view rather than a proliferating page mode. |
| **P1 — native rendered preview needs interaction/fidelity gates** | `NativePreviewBuilder` now emits bounded (16 Ki characters/120 lines), format-specific text and source-mapped spans: Markdown headings/lists/fences, CSV columns and structured trees; Win32/AppKit apply semantic colors/fonts. The spans are carried to the shells for styling, but no preview-to-source navigation callback is exposed in `INativeEditorShell`, and image/link interaction is not implemented. This is materially beyond the former 40-line outline, but not a complete rich document preview. | **Native desktop + Formats.** Use fixtures for Markdown heading/list/fence/link/image, CSV quoted newline and nested JSON/TOML/YAML; verify styled source maps, safe link behavior, keyboard/pointer navigation back to source, and truthful truncation. | Bounded source-mapped native rendering supports the promised interactions or clearly declares unsupported rich elements; no browser or sidecar. |
| **P1 — native input, accessibility and distribution trust need target-OS evidence** | Win32 RichEdit and AppKit `NSTextView` provide mature OS text input, but source-level use is not proof of Chinese/Japanese IME, emoji/grapheme caret, mixed-newline round-trip, keyboard shortcuts, screen-reader exposure or high-DPI behavior in mote. Current native GUI smoke closes after showing a window; it does not edit/save. A raw Mach-O one-binary deliverable needs an explicit signing/notarization and launch plan, separate from the file-count gate [Apple notarization](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution). | **Native desktop + Verification/CI.** Record Win/mac open→IME compose→undo→save/reopen, VoiceOver/Narrator, selection and all themes; launch from a clean directory. Sign/notarize the actual one-binary artifact and test Gatekeeper without silently wrapping it into a noncompliant `.app`. | Native workflows pass on both OSes; signing/trust and delivery method are explicit; no sidecar is introduced. |
| **P1 — configuration and theme integration need OS gates** | `MoteConfigLoader` implements default `~/.mote` paths and overrides without creating directories on read; telemetry accepts `config.TraceDirectory`. `Mote.Native.Program` now passes `shell.PrefersDark` to `ThemePolicies.Resolve`; Win32 and AppKit provide OS appearance queries. Static contrast tests and the presence of those queries do not yet prove dynamic OS appearance handling or applied selection/control foregrounds on both platforms. | **Native desktop + Configuration/Themes + Verification.** Use a temporary user home and `MOTE_HOME`, vary `config.toml` paths, enable tracing, and assert all runtime files appear only in resolved destinations. Toggle OS light/dark and inspect `system` resolution, selection and buttons in all themes. | Defaults/overrides work end to end; `system` reflects OS appearance or explicitly reports fallback; no bundled theme/font file or implicit runtime write beside binary/edited file. |
| **P1 — latency evidence does not yet establish “instant” native editing** | Scheduled `.github/workflows/benchmarks.yml` runs headless open/edit/Markdown workloads and uploads JSONL; it does not measure native first editable frame, IME/edit-to-paint p95, long-line scroll, whole-page diff cost or peak RSS of the one-binary GUI. `NativeEditorController` copies/normalizes a page and `NativeTextProjection.Difference` scans it after changes. | **Large-file UI/perf + Verification.** Run native AOT on matched Win/mac runners with 1/10/100 MiB and a 50 MiB line; capture cold/warm start, open-to-editable, p50/p95 input-to-visible-presentation, scrolling, allocations/RSS and telemetry on/off. Store CI results under repo `.cache` and project experiments under `.temp`. | Reproducible OS-specific baselines and regression thresholds grounded in observed workloads. |
| **P1 — trace correlation ends at presentation, not actual compositor paint** | Telemetry sink, `~/.mote/traces` default, privacy schema and health accounting are implemented. Native controller starts an edit mark **before** engine Apply and records `EditToPresentation` after `SetAnalysis`, an honest name; it does not assert pixels reached the display. `EditToPaint`/view-paint measurement remains a future UI hook. Native status exposes degraded tracing, fixing the former silent-fault gap. | **Native desktop + Telemetry + Verification.** With opt-in tracing, inspect one edit's commit→parse→presentation trace IDs; add a platform frame/paint completion hook only if it observes actual draw timing, then compare with screen-capture or OS frame probe. Force queue overflow/write failure and confirm degraded status without blocking edits. | End-to-end claims use measured endpoints, privacy remains intact, and overhead is quantified; presentation is never mislabeled as paint. |
| **P1 — residual Save/Save As race and native picker integration** | Same-path Save hashes original bytes; default Save As refuses an existing different target, while explicit `FileOverwriteToken` authorizes replacement. Native controller now performs its **own** `ConfirmOverwrite(path)` before `SaveOverAsync`, so it no longer relies solely on native panel behavior. [Code review](code-review.md) verified the engine contract locally. A narrow verification-to-`File.Replace` race remains, and actual Win/mac picker-confirmation flow is not GUI-tested. | **Engine + Native desktop + Verification.** On both OSes cancel an existing-target Save As and compare bytes, then confirm replacement; use a deterministic writer barrier to characterize remaining TOCTOU race. | Explicit user intent precedes every overwrite and the concurrent-writer guarantee is stated accurately, not promised as perfect atomic detection. |

## Do not resurrect resolved findings

Earlier audit rows about metadata-only Save conflict detection, unordered `Changed` events, unconditional in-flight Open replacement, no-op Markdown/TOML/YAML formatters, and scalar-only YAML duplicate detection are stale. Engine now fingerprints bytes and queues notifications; Open reconfirms; formatters have conservative nonidentity implementations; YAML uses tag-aware canonical/structural comparison and warns where equality cannot be decided. Keep regression tests, but reopen only with fresh failure evidence. The strict one-binary CI gate and integrated native workflows are now the decisive release frontier—not polishing the noncompliant Avalonia package.
