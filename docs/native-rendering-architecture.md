# Native rendering architecture: bounded semantic presentation, native interaction

Status: **target architecture and implementation contract**, 2026-09-30; not an implemented renderer or release acceptance. Inspected source checkpoint: `f2b8686` on `codex/initial-product`. This decision extends [architecture](architecture.md), [preview navigation](native-preview-navigation.md), [semantic IR evolution](semantic-ir-evolution.md), [themes](themes.md), and the rendering row in [release gaps](release-gaps.md). It does not change the strict one-binary delivery rule, the source editor, or any established format API.

## 1. Decision and representative workflow

**Keep the engine as the only text owner. Let format sessions produce bounded, typed rendering projections from their private syntax/semantic state. Use the existing OS-native read-only rich-text controls for a Flow surface, and native virtual table controls for a CSV Grid surface. Do not introduce a browser, a universal document AST, a general widget framework, or a second editable rendered document.** Native preview selection, Copy, focus and accessibility are existing user-facing behavior and must survive this evolution.

The dominant workflow is Open → immediately editable source → useful formatted preview and diagnostics → optional source navigation → edit → updated preview → exact Save. Rendering never gates source readiness or Save. Markdown needs actual paragraph/inline structure, not just an outline; CSV needs actual cells, not space-padded strings; JSON/TOML/YAML need readable typed structure with source-backed navigation, not a claim of WYSIWYG editing. Plain text needs faithful selectable text. Two concrete surface families cover these needs without six platform UI implementations.

The policy also declares a small **presentation capability/default** (`SourceOnly` or `SourceAndPreview`), separate from semantic completeness. Plain text's ordinary display defaults to full-width source because duplicating identical text adds no useful rendered information. Its bounded Flow preview remains available on explicit request and for compatibility. Native applies an `auto` convention, then explicit user preview/split preference overrides it; it does not hard-code `if PlainText` pane logic throughout the shells. Structured formats have useful preview semantics even while analysis is pending, so they show an honest loading/provisional state rather than a blank half-window. Preserve explicit split choices and legacy behavior; do not introduce a project sidebar or workspace chrome.

```text
Engine Document / immutable snapshot v
       │ committed edit chain; bounded source-interest intervals
       ▼
One serialized format session
  private parser / semantic index / dependency certificates
       ├── current semantic truth, diagnostics, source tokens
       └── bounded presentation: Flow paragraphs/runs OR Grid rows/cells
                           │ generation + version + request identity
                           ▼
Native controller: resource authorization + theme/layout generations
                           │ prepared immutable presentation
                           ▼
Win32 RichEdit / virtual ListView       AppKit NSTextView / NSTableView
  installed presentation identity + native selection + actual OS geometry
                           │ explicit source/open-target action
                           ▼
Controller validates identity/action → Engine source selection or OS opener
```

No platform callback parses, scans a file, waits for analysis, downloads an asset, or performs an engine edit. It reads the currently installed bounded model or returns a pending/unavailable state and schedules work.

## 2. Ground truth: useful existing implementation, real missing information

`NativePreviewBuilder` currently emits text plus `NativePreviewSpan` item-origin mappings, capped at 16 Ki UTF-16 units and 120 lines. Markdown headings/lists/quotes/code are readable, CSV is limited to eight padded columns, and structured formats are indented labels. RichEdit and NSTextView apply styles and preserve native selection/Copy. Navigation is an explicit stamped offset-to-source operation; ordinary click/Enter/Space means **reveal source**, not launch a link. This is a useful compatibility baseline, not complete rich rendering.

The current public `SemanticNode` is insufficient to recover faithful Markdown inline layout. `MarkdownPolicy.Project` deliberately omits `LiteralInline` children and uses flattened `InlineText` as heading/paragraph `Value`; remaining children contain semantic constructs but not a complete ordered literal/inline stream. Emphasis strength, list starting ordinals, precise transformed-text mapping, and some layout distinctions are not fully expressed. Native must not guess syntax from flattened values, infer glyph offsets by subtracting Markdown markers, or call `RenderHtml` and reparse its output. `RenderHtml` itself reparses for the compatibility HTML API; it is **not** the native hot path.

Produce the new rendering data while policy-private parsed state is available. For Markdown this means walking Markdig block/inline data inside the session's bounded projection work; for large certified blocks, retain or recreate only the required certified block from the authoritative snapshot. Recreating a bounded block inside its owning policy is acceptable where measured; reparsing the entire file in Native is not. Streaming policies must add sufficient bounded render metadata at their existing semantic projection point. Existing string `Analyze`, `Format`, `RenderHtml`, `SemanticNode`, and `IFormatSession.Analyze` contracts remain intact; this is an **additive internal capability**, not a public breaking rewrite.

## 3. Ownership and types

| Owner | State | Contract |
| --- | --- | --- |
| Engine | Source, versions, file identity, encoding, Undo/Redo | Only explicit engine transactions change text; rendering cannot clear dirty state or normalize bytes. |
| Format session | Private syntax/index and semantic dependency evidence | One session per document; calls serialized; canceled work cannot commit a new cache version. |
| Format projection | Flow/Grid contents, semantic roles, absolute source origins | Immutable, bounded, no native handles and no retained whole-file string/snapshot. Every origin belongs to exactly one version. |
| Native controller | Preview interest, presentation sequence, authorized resource requests, current theme | Latest request wins; same-version request changes still invalidate old actions. |
| Platform surface | Native control objects, selection, scroll, installed identity, layout | UI-thread lifetime; old models remain alive only while installed or explicitly preparing replacement. |
| Resource service in Native | Authorized handles, bounded decoded images, resource revisions | Optional derived I/O, never canonical document text; cancellation and eviction release handles/buffers. |

Suggested types below describe **semantics**, not today's declarations. Keep them internal initially; do not expose policy owner IDs or native objects as public APIs.

`PresentationId` belongs to Native: Formats knows snapshot versions but must not reference `NativeDocumentStamp` or a shell type. The projection/evidence types belong at the additive Formats capability boundary (or an internal shared rendering-contract module if assembly visibility requires it), below Native and above no UI dependency. Per-window delivery stays with the concrete body: Grid can retain/adapt CSV's existing `WindowProjection`; Flow must not manufacture CSV row/index fields for a text paragraph.

```csharp
/// <summary>One installed view, including changes that do not edit source.</summary>
internal readonly record struct PresentationId(
    NativeDocumentStamp Document, long Sequence);

/// <summary>Truth and delivery are independent of visible layout.</summary>
internal sealed record PresentationEvidence(
    AnalysisCompleteness Semantics,
    IReadOnlyList<TextSpan> CertifiedCoverage,
    int? TotalDiagnosticCount,
    bool ProjectionTruncated);

/// <summary>Text origin precision; decoded/truncated text is not assumed affine.</summary>
internal enum OriginPrecision { Item, ExactText }

/// <summary>A visible run's origin in one source version, not an inverse editor.</summary>
internal readonly record struct RunOrigin(
    TextSpan DisplayRange, TextSpan SourceRange, OriginPrecision Precision);

/// <summary>A bounded policy result; the body has exactly one concrete surface kind.</summary>
internal sealed record RenderProjection(
    long Version, PresentationEvidence Evidence, RenderBody Body);
```

`RenderBody` is a closed Flow/Grid choice, not an extensible widget hierarchy. Flow contains a bounded display-text buffer plus ordered paragraphs, disjoint inline style runs, source origins, explicit action ranges and image slots. Grid contains bounded visible row/cell descriptors plus source origins and ordinal evidence. Both may have non-navigable status/omission notices. A small discriminant and concrete immutable structures are sufficient; no reflection, runtime factories, visitor framework, or custom plugin ABI is needed.

Flow paragraph data needs kind, heading level, logical list marker/start, nesting depth, spacing/indent role, inline run interval and owning source span. Inline data needs semantic foreground role and flags for strong/emphasis/code/link; nested flags are flattened into non-overlapping display runs with deterministic precedence. Resolved destinations and image alt text are separate typed fields, never overloaded into a text color or generic `Value`. Native themes decide actual font/color/border values. Policy-private trees remain richer than the rendering projection.

Grid cell data needs logical row/column when proved, decoded bounded text, exact cell source span, value/clipping state and optional tentative scalar classification. CSV inference is not validation. A first-row header hypothesis must be labeled inferred until explicitly chosen; do not promote every first row to a header by rendering convention. A missing field is different from an existing empty field. A quoted newline is not a new row; display it as multiline text where supported or an explicit line-break indicator with a complete bounded detail view. Copy follows a defined decoded-cell/TSV operation; it never silently substitutes the file's original CSV bytes.

### Origin and action invariants

1. Offsets are absolute UTF-16 source coordinates; display text has its own bounded UTF-16 coordinate system. No use of UTF-8 byte offsets at this boundary.
2. An `Item` origin navigates to the semantic item's start. `ExactText` is allowed only for an unchanged literal slice with verified matching length/text. Markdown `&amp;`, escapes, CSV `""`, emoji clusters, synthetic list bullets, ellipses and image replacement characters are not affine source mappings.
3. Exact per-character maps are unnecessary for the current reveal-source action. If a future source-range selection requires them, emit explicit transformed segments rather than interpolating between endpoints.
4. Synthetic decorations are non-navigable. Visible truncated prefixes may retain their item origin; the omission marker and hidden suffix have no inferred hit target. Cut on grapheme boundaries when practical; never emit a lone surrogate by slicing at a resource cap.
5. Source and external-target actions are distinct. Existing unmodified activation remains reveal-source. A context command/explicit modifier or accessible action opens a separately authorized target. No automatic link detection in a native text control may bypass this distinction.
6. Shell actions carry the **installed** `PresentationId`, not merely the last requested `NativeDocumentStamp`. The controller resolves action IDs/ranges only against that exact installed immutable map.

The sequence is necessary now, not speculative machinery: scrolling a pinned preview, switching a format, a same-version idle Full result, an image completion and a font/theme layout change can all produce different maps at the same source version. UI text, attachment character positions and maps must install together. A prepared model receives an install acknowledgement or the shell stamps callbacks with the retained model itself; the controller cannot assume an asynchronously prepared result is already displayed.

## 4. Bounded requests and honest coverage: one window first

The current UI follows the source viewport. **It does not need two disjoint source windows simply because CSV now implements `IWindowedFormatSession`.** Continue to request one `AnalysisRequest.VisibleRange` where source decoration and preview share interest; reuse the same result/projection. Duplicate analysis jobs would add cost and concurrency hazards without a user benefit.

A detached/pinned preview or independently scrolling Grid has a real second interest. At that point the Native session driver normalizes `[source viewport, preview source interest]`: overlapping/touching ranges merge; disjoint ranges remain separate; limits apply to their union. For CSV, call the committed optional `AnalyzeWindows` **once** with the contiguous edit chain and normalized windows; derive source tokens from the source window and cells from the preview window. No second session, second text buffer, or convex-hull claim is created. Requests and render projection construction run on the same serialized driver so no update interleaves between the semantic result and its derived render data. For other formats without the optional capability, preserve serialized one-window work and explicit per-result coverage, or keep preview following source until a format-specific batch implementation is justified. Do not combine two counts or call a partial union `Complete`.

Use current `WindowedAnalysis.CertifiedCoverage`, `Windows[].SourceIndexed`, `Truncated`, and global `Completeness` directly. `SourceIndexed=true` establishes that an index reached a requested interval, **not** that every semantic dependency is resolved. `Complete` certifies full validation with a total diagnostic count, **not** complete rendering or a reusable full row index. A Full streaming fallback can certify all source while returning sparse nodes and retaining no navigable row index. Never infer a global row count or arbitrary row lookup from `Complete` alone.

For a cold giant CSV row or a distant window not yet reached, show pending/provisional status, not an empty-valid grid. `CoveredRegion` uses a non-convex interval set; its gaps are not validated. Old-version evidence cannot be shifted generically through edits: certified dependency ownership is policy-specific. Preserve visible good text for reading only if distinctly marked stale; clear/disable all old-version actions immediately. Ordinary source editing remains available while indexing catches up.

Initially the preview is a bounded source-interest neighborhood with explicit previous/next/source-follow navigation, not a fictitious full rendered scrollbar whose total extent is known. A full logical CSV scrollbar becomes available only when the policy separately provides an exact row-count/checkpoint capability at this version. That capability must have a bounded index or streaming fallback consistent with [CSV sparse projection](csv-sparse-projection.md); its proposed 32 MiB retained-index budget is not currently proved. Never populate a native control with guessed rows that look authoritative. Source navigation remains global independently of preview extent.

## 5. Native surfaces and the rendering cost decision

| Approach | Correctness and operational cost | Decision |
| --- | --- | --- |
| HTML/WebView/JCEF/WebKit preview | Mature CSS layout but browser trust/runtime/asset surface; risks hidden network and extra dependencies; diverges from strict native product. | Rejected. Existing safe HTML compatibility API remains non-product tooling. |
| One full custom cross-platform canvas | Flexible shared geometry, but needs new preview selection, keyboard semantics, links, text-range accessibility, images, bidi hit testing and reader acceptance on both OSes. Existing source canvas does not automatically supply these. | Do not replace proven native text preview by default. Revisit only if a discriminating native-control fidelity/performance gate fails. |
| Native rich text Flow plus native virtual Grid | Reuses OS shaping, selection, scroll/Copy and much accessibility; adapters differ but public rendering semantics remain small. Bounded input avoids whole-file native layout. | Chosen. Test unsupported control features; do not assume native means automatically correct. |

### Flow: RichEdit and NSTextView

Windows retains system `Msftedit.dll`/`RICHEDIT50W`, emits one escaped bounded RTF text/style projection, and applies it in a coalesced transaction with exact text/origin readback and installed identity. Do not resurrect the per-token selection-format loop at rich inline scale: [measured RichEdit evidence](native-richtext-performance.md) already shows it is expensive. Preview-only RTF changes do not affect source Undo or composition. Disable uncontrolled URL detection, embedded objects, drag import and external field execution; image insertion is an explicit separately tested path. Never feed user RTF to the control: only mote-generated escaped RTF exists here.

macOS retains a selectable read-only `NSTextView`; construct bounded attributed text and paragraph styles directly, not through an HTML importer. Build plain decoded data off-thread; construct/install AppKit objects and attach delegates on the UI thread. Disable editing/import and delegate link activation to the controller. Native text layout supplies font fallback, bidi, ligatures, wrapping, selection and native text accessibility; actual behavior still needs target tests. If Core Text helpers are used, Apple specifically requires individual layout objects to stay within one operation/work queue/thread; thread-safe functions do not justify sharing `CTLine`/`CTFrame` across concurrent layout jobs ([Core Text](https://developer.apple.com/documentation/CoreText)).

Paragraph-specific headings, nested list indents, code fonts/background, emphasis and quotations use typed native paragraph/character attributes. A decorative rule or quote border may use a bounded native drawing decoration, but must not become navigable text or a platform-specific parser. Native typography is allowed to differ slightly across OSes; equal semantic contents, origins, actions and accessibility are required, not pixel-identical pages.

### Grid: ListView and NSTableView

Windows uses a report-style virtual `ListView` with `LVS_OWNERDATA`; macOS uses `NSTableView` with a retained data source/delegate and reused cells, constructed programmatically (no nib). These controls are mature production mechanisms: Microsoft's [virtual ListView sample](https://learn.microsoft.com/en-us/windows/win32/controls/vlistvw-sample) populates display data on demand rather than adding every item; Apple's [NSTableView documentation](https://developer.apple.com/documentation/appkit/nstableview) likewise describes data-source lookup and reused views.

The table callback reads only a ready bounded cache. Cache misses display a clearly pending cell and enqueue projection; never scan CSV synchronously from `LVN_GETDISPINFO`/an AppKit data-source callback. Keep the policy index private; the controller asks for a bounded range by source anchor or, only with an explicit certified row-index capability, row range. Projection cells carry their source spans. UI logical row positions do not become file offsets.

Native tables are generally row-selecting, not spreadsheet editors. Supply a focused-cell cursor above their mechanism, with Arrow/Tab navigation and source activation, while leaving native pointer selection and Copy behavior coherent. Cell semantics/accessibility must expose row/column and multiline/clipped state; default row-only accessibility is insufficient evidence. Sorting/filtering is not silently enabled: the dominant view preserves source order. Hundreds of thousands of source columns do not imply hundreds of thousands of native columns; show a bounded column window with explicit horizontal navigation/omission. Read-only source navigation is the present contract; a future cell editor must use a format-proposed versioned text edit, not mutate Grid data.

## 6. Per-format fidelity and unsupported constructs

| Format | Required presentation | Semantic limitation must remain visible |
| --- | --- | --- |
| Markdown | CommonMark paragraph/headings (ATX/Setext), strong/emphasis/code in source order, ordered/unordered nested lists with original start, quotes, thematic break, code blocks/fences, soft/hard line breaks, resolved links and image alt/slot. | Raw HTML is non-executable literal text under existing `DisableHtml`; unresolved references are not invented links. Existing restricted large-file certificates remain restricted. GFM tables/math/Mermaid are separate format extensions, not silently claimed CommonMark features. |
| CSV | Actual bounded rows/cells, source ordinals when known, distinct empty/missing fields, quoted multiline content, horizontal column windows, width diagnostics. | Header/type guesses labeled tentative; row extent/indexing and projection clipping differ from global validation. |
| JSON | Source-ordered object/array hierarchy with typed scalar previews, duplicate-name diagnostics and scalar origins. | Duplicate properties must remain visible; never convert to a dictionary that overwrites them. No invented schema or locale-dependent number conversion. |
| TOML | Table/array-table sections, typed key/value presentation, comments/trivia retained in source, navigable exact spans. | Display source-backed entries rather than coalescing distinct array-table instances or implying unsupported ownership paths have been checked. |
| YAML | Document/sequence/mapping structure, tag/scalar roles, anchor/alias identity and explicit errors. | Render aliases as references, not recursively expanded values; cycles and unknown key equality do not create an infinite tree or false duplicate-key proof. |
| Plain | Selectable bounded faithful text with correct line boundaries and original source mapping. | Tabs/controls/long-line clipping explicit; preview never changes Save bytes. |

A recovered unsupported construct renders an explicitly labeled source excerpt or error placeholder with its item origin, not silently omitted content that looks like complete fidelity. Projection omission markers report **display truncation**, independently of diagnostic totals. Diagnose syntax/semantic errors from policy output; do not invent renderer errors as language invalidity.

## 7. Link and image safety: opening a file is not executing a document

Format parsing identifies a destination; Native authorizes the **effect**. A policy's existing `SafeUrl` check is not a filesystem/network permission. Put this separation in types: `RenderDestination` (parsed untrusted data) → `AuthorizedOpenTarget` / `AuthorizedLocalImage` (controller decision) → OS operation. Never pass a raw Markdown URL directly into `ShellExecute`, `NSWorkspace`, an image decoder or an HTML importer.

Defaults: no automatic network fetch, no script/custom command schemes, no remote file/UNC reads, no remote images on Open. Allow explicit user launch of normalized `https`/`http` and, if deliberately supported, `mailto`; show destination for an external action and use OS opening without shell command construction. Reject controls/embedded NUL, malformed/ambiguous URI forms and executable schemes such as `javascript`, `data`, `command` and `vbscript`. An explicit permitted external link is not a trusted image fetch. Fragments resolve only through the current format's supported heading/reference rule; unresolved/ambiguous fragments reveal source or report unavailable.

Local relative raster images may load lazily when their slots are visible, inside a narrow document-directory authorization. **Authorization must precede any path-following open**: checking a final path after an ordinary open is too late to guarantee zero automatic network I/O. Reject UNC/remote URI roots, mapped network drives and remote-mounted resource roots before opening the resource; a local-looking spelling does not establish locality. An explicitly opened source file on a network volume does not implicitly authorize fetching its linked images. If the adapter cannot establish a local authorized root without speculative resource access, show `Blocked` instead of probing it with a following open.

Starting from an authorized local directory handle, use controlled non-following component traversal or an equivalently verified handle-based strategy. Normalize/validate relative components (`..`, platform path casing, URI decoding exactly once) before traversal. Intermediate symlinks/reparse points matter just as much as the final component: a final-component-only no-follow flag or a prior string/metadata check is **not** a cross-platform race-safe proof. Microsoft's [reparse-point file-operation guidance](https://learn.microsoft.com/en-us/windows/win32/fileio/reparse-points-and-file-operations) illustrates why ordinary file operations require special treatment; it does not establish a complete mote traversal implementation. The safe automatic default rejects redirecting components; any permitted traversal must prove that each step remains within the authorized local directory/volume without first following an untrusted redirect. If a supported platform API strategy cannot provide that proof, return `Blocked`; do not invent a common Windows/macOS no-follow guarantee or weaken the default to a best-effort pathname check. Explicit user authorization of another resource is a separate effect with its own stated scope.

After obtaining the authorized final handle, verify the final identity/containment as defense in depth and read/decode from **that same retained handle** (or bounded bytes read from it), never reopen its pathname. This avoids a check-to-reopen race; it does not claim that same-handle bytes cannot be concurrently modified. Treat concurrent content changes as untrusted decode input and keep the resource revision/budgets honest. Platform implementations and target adversarial tests must establish the actual guarantees before local automatic image loading is enabled. An unsaved document has no implicit asset directory. Do not create image companion files in the source directory; temporary/cache data uses configured `~/.mote/cache` by convention, with overrides. Default in-memory caching avoids unnecessary copies; persistence must respect privacy/eviction.

Use OS decoders (Windows WIC, macOS ImageIO) for allowlisted raster formats; inspect dimensions/decoded-byte estimates before full decode, downsample to slot display size, cap input bytes/pixels/concurrency and bound encoded text. SVG, HTML, PDF and animated/network resources require a separately specified safe path; display alt/unsupported state rather than letting a generic OS loader choose arbitrary document plugins. Raw image text is never executable.

Image slots have `Pending`, `Ready`, `Blocked`, `Unavailable` or `TooLarge` state, alt text, source origin and resource revision. Their state is not a source edit. Completion installs a new presentation sequence; a callback for an old slot/document/version cannot replace the new one. Keep source and preview scroll anchored to semantic origins across image-height changes. Native attachment APIs are candidates, **not target proof**: Apple's [NSTextAttachment image property](https://developer.apple.com/documentation/appkit/nstextattachment/image) supports the model; Microsoft's [EM_INSERTIMAGE](https://learn.microsoft.com/en-us/windows/win32/controls/em-insertimage) documents insertion, but actual system `Msftedit.dll` support, scaling, replacement-character offsets, alt accessibility and bounded memory must be probed on both Windows RIDs. Do not import Office's RichEdit DLL or invent an OLE compound-file subsystem to avoid this gate. If native insertion fails, a small explicit image-slot drawing adapter with native accessible alt/action is the next measured candidate; unsupported image placeholders are not a final full-fidelity pass.

The security stance deliberately differs from VS Code's web preview, whose documented [Strict mode](https://code.visualstudio.com/docs/languages/markdown#_markdown-preview-security) allows HTTPS resources while disabling scripts. Mote has no workspace trust or browser origin boundary; no automatic remote resource loading is a smaller, clearer default.

## 8. Scheduling, invalidation, composition and bounded lifetimes

On edit, immediately invalidate preview actions for the prior version. Schedule bounded semantic/render work behind source input; commit semantic state only under the policy's normal cancellation/version rules. Build decoded text/style/origin metadata off the UI thread; the final native install is bounded and coalesced. Theme palette changes invalidate color application only; font/DPI/width changes invalidate native layout; neither reparses source. Format switch/close changes document generation and cancels/releases every pending render/resource job.

An active source IME composition vetoes preview navigation without forcing commit, preserving today's contract. Source tokens/theme changes follow existing composition deferral. Preview-only paints need not block on source preedit if they never touch first responder, source native text, selection, input-island geometry or candidate state; otherwise defer. No preview update calls `CommitPendingText`. Explicit source/navigation commands retain their established composition semantics. Preview remains read-only and owns no IME or source Undo state.

View state is anchored by source item/cell span plus a local display selection, not an ordinal that changes when records merge. Across new versions, translate only anchors safely mapped by the engine edit chain; when deleted or ambiguous, choose an explicit nearest source boundary and clear display selection. Don't reuse policy node identity across sessions. Theme/width/resource-only updates preserve source selection and preview scroll/selection where the displayed text still matches. Data installation failure leaves source usable and a truthful preview-unavailable notice; it does not mutate source or silently use a mismatched map.

Start with current 16 Ki text/120-paragraph-or-row display cap, plus independent run/action/attachment/cell caps and aggregate decoded-byte caps. Count budget **before** constructing strings or decoding values; `Split` on an entire giant code block followed by `Take` is not bounded work. For Grid, projected cell budgets are independent of rows and shared fairly across requested windows (the committed CSV contract already documents this). Do not apply 16 Ki text caps to raw encoded image hex and assume memory is bounded. Keep at most installed + newest prepared model, capped decoded image cache, and a bounded scheduling queue; release native objects when replaced/closed. Set precise initial asset/run/cell budgets in the implementation with adversarial tests and measured tuning, not as unearned memory claims here.

100 MiB behavior uses the same exact Engine text, not a read-only fallback. Rendering costs scale with admitted projection contents rather than whole-file length; policy full validation may still be O(file size) and must be cancellable/asynchronous. A 50 MiB single paragraph/CSV record is a distinct adversary: return a bounded excerpt/cell segment with explicit omission, not a 50 MiB normalized `Value` copied first. Source Canvas horizontal editing remains unchanged. Whole-document pretty printing, image decode and native text layout never run synchronously per key.

## 9. Accessibility and themes are contracts, not decorations

Preserve one editable source identity (`Mote editor`) and a distinct read-only `Mote preview`; do not hide the useful preview or duplicate source in an invisible full native buffer. Native control text accessibility is a valuable base, not proof of semantic heading/link/image/cell roles. Add explicit actions/annotations where native providers omit them, deriving text, bounds and origins from the installed model. A reader sees status for provisional/truncated content and can reveal source using the same validated action. Links expose destination/action; images expose alt/state; table cells expose row/column and clipping. Never set accessible names to document paths or unbounded source contents.

Read-only Copy and selection remain native for Flow. Grid supports clear cell/row selection and bounded decoded Copy; global source Copy remains the controller's separate operation. Selecting text, browsing with a reader or tabbing to a link must not launch a URL or change source. Test actual Narrator/VoiceOver, not only UIA/AX properties, before declaring reader acceptance. A failed semantic accessibility decoration cannot crash the source editor; do not label the rich preview accepted until its required interaction is actually usable.

`IThemePolicy` remains the sole visual policy; format output uses role names/flags. Extend typed roles for paragraph, heading levels, inline-code foreground/background, quotes/rules, Grid header/cell/border and blocked/pending assets as needed, with restrained VS Code/JetBrains-inspired defaults. Resolve brushes/fonts once per theme/layout generation, not per token/cell. The recommended user-editable palette data below lives under `~/.mote`, never in loaded code. OS high contrast and selected text override semantic colors where needed. Palette tests cannot prove actual native selection/chrome/attachment contrast. Color-only changes must not change source version, trigger parsing or break preedit. [VS Code's role reference](https://code.visualstudio.com/api/references/theme-color) and [JetBrains color/font guidance](https://www.jetbrains.com/help/idea/configuring-colors-and-fonts.html) support separating editor/preview/chrome roles rather than making every surface inherit one background.

### User-editable palette decision

The current static `ThemePolicies` and built-in ID selection satisfy policy selection, **not arbitrary user color editing**. The user explicitly asks that settings be easy to modify and that convention precede overrides. Recommendation: make **data-only color overrides** part of the finished theme/configuration contract, while retaining bundled immutable policies as defaults. This extends rather than replaces the strategy: `validated override data + bundled IThemePolicy → immutable composed IThemePolicy`. No runtime DLL, assembly loading, CSS engine, arbitrary expression evaluator or reflection-based registry is involved.

Use a bounded typed table in the existing `~/.mote/config.toml` (example target shape, not implemented settings):

```toml
[appearance]
theme = "mote-dark"

[appearance.colors]
"preview.background" = "#202124"
"preview.foreground" = "#DADCE0"
```

Known role keys map to a closed schema; omitted keys inherit the selected base. Accept an explicit, narrow opaque RGB grammar initially, rather than ambiguous color names/alpha whose composited contrast depends on unrelated backgrounds. Unknown keys, malformed values, too many entries and excessive file size yield actionable nonfatal config diagnostics, not code loading or startup failure. Construct the entire candidate palette, then run the existing contrast validator over semantic/selection/chrome/preview/Grid pairs. If the **composed palette** violates the contract, reject the override set as one unit: retain the last valid palette on reload, or the valid base on initial startup. Do not silently accept some colors and produce an untested mixture. Report offending roles and the fallback in persistent nonmodal status/config diagnostics. Theme selection fallback rules remain compatible with current unknown-ID behavior.

Load this small data once with startup configuration, before brush creation; use existing startup file limits and add bounded role/entry counts. Explicit Reload Settings is sufficient initially; filesystem watchers are not necessary on the source-readiness path. Reload resolves/validates off the critical input path and applies one immutable policy atomically using the existing real-composition deferral. Share policies across windows, keep override origin/diagnostics in Configuration, and keep Themes free of filesystem I/O. A later typed system-font/size override must validate metrics and trigger layout generation, not read shipped font sidecars. Runtime configuration/cache/traces under `~/.mote` are user data, **not shipped companion binaries**; this does not weaken strict one-executable delivery.

This fixture does **not** prove that production Plain preview is empty: `NativePreviewBuilder` actually duplicates bounded source text for Plain. The source-only default is a workflow judgment about a redundant preview, not a guessed rendering bug. The image supplies scoped chrome evidence, not a diagnosis of semantic analysis or every theme. It establishes that restrained text colors alone do not deliver the requested coherent product appearance.

Treat menu/chrome surfaces, splitter, status, focus indicators, paragraph spacing and useful pane choice as presentation policy. Default source-only Plain removes the wasted pane rather than adding a compensating empty illustration. For structured previews provide a labeled header/status, readable padding and hierarchy, sensible resizable split width, document-appropriate paragraph/heading/code typography, and loading/error/empty-document messages tied to actual state. Theme/font/spacing remain distinct from source semantics. No decorative startup asset or expensive animation is justified.

On Windows use [documented menu/owner-draw mechanisms](https://learn.microsoft.com/en-us/windows/win32/menurc/using-menus#creating-owner-drawn-menu-items) where needed (`WM_MEASUREITEM`/`WM_DRAWITEM`, explicit label/accelerator data and native menu keyboard/accessibility contracts) and [supported title-bar appearance APIs](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/ui/apply-windows-themes) on supported OS versions. Do not rely on undocumented `uxtheme` ordinal exports, globally forced theme modes, Office DLLs or hooking all system controls. Owner-draw is not permission to replace menus with inaccessible colored rectangles; Alt/mnemonic navigation, disabled/hot/selected/high-contrast states, popup menus and reader names must remain native/coherent. On macOS follow AppKit's system menu/appearance conventions rather than forcing a Windows-style application menu strip. System dialogs and other OS-owned surfaces may legitimately follow OS appearance; mote-owned panels must not accidentally remain stark white in its dark palette.

Validate these decisions with rendered screenshots and real menus at 100/150/200% Windows scale and standard/Retina macOS, in dark/light/high contrast, including selected text, hovered/disabled controls, focus, pending preview and an empty document. Borders should be deliberate theme-valued separators, not a hard-coded bright frame; required focus/interactive boundary contrast still follows the existing accessibility contract. Screenshot reviewers must distinguish a legitimate OS-owned light menu from an unstyled mote-owned surface and must not infer successful interaction from appearance alone.

## 10. Integration order: complete design, coherent implementations

These are integration slices of one target product, not permission to redefine completion as a minimal preview. Each slice preserves current userspace and has a rollback before adoption.

1. **Projection and installed identity:** add bounded Flow/Grid data and an optional internal rendering capability in Formats; preserve all old signatures. Connect to the serialized Native session driver and exact installed presentation sequence. Initially adapt existing text-only previews into the new envelope. Differential tests prove unchanged current plain/text/item navigation, source/Undo/Save and `--legacy-page`; same-version A/B installation tests prove actions resolve the shown map.
2. **Faithful Flow projection and coherent shell layout:** implement ordered Markdown literal/inline/paragraph metadata at the Markdig session projection point, with bounded decode. Structured/Plain policies emit Flow without reparsing in Native. Build RichEdit RTF and AppKit attributed-string adapters with exact display readback and native selection preservation. Apply policy-provided auto pane capability, meaningful pending states, native chrome/typography and validated data-only palette overrides. Gate CommonMark fixtures, Unicode layout, source actions and actual dark/light/high-contrast menu/pane screenshots on both OSes; do not claim inline fidelity from a flattened heading test or product polish from a palette unit test.
3. **CSV Grid and real independent interest:** implement native virtual tables/cache-miss scheduling, source-backed cells and accessible cell focus. Keep one-window source-follow default. Use CSV `AnalyzeWindows` only for independently scrolling/pinned preview; enforce fair cell budgets, truthful delivery and exact diagnostic totals. Add a bounded row-index/extent capability only if full logical preview scrolling is actually implemented and its retained-index cost passes.
4. **Safe resources and effects:** implement target authorization, explicit external-open command and lazy local raster slots. First run the system attachment/offset/reader capability probes; then finish the chosen bounded native attachment/drawing route. Disabled network must be observed by a test, not merely documented. One-file inventory/import gates reject any browser/Office/font/helper sidecar.
5. **Product acceptance and default rollout:** run published Native AOT four-RID suites with actual pointer/keyboard/focus, exact Save/reopen, real composition and readers, all themes/DPI, adversarial size and controlled cold/warm timings. Keep legacy preview rendering as an internal fallback while parity is not established; keep source `--legacy-page` rollback independently. Remove a fallback only with scope-matched evidence, not because managed tests are green.

Suggested file ownership: Formats owns rendering contracts and each format's projector/session; Native controller owns publication/resources/action authorization; Windows/Mac own their adapters; Themes owns style roles; validation owns fixtures/hosted probes. Public/internal contract changes are coordinated before parallel writers start. Engine should receive **no** Markdown/CSV/image/layout types in this work.

## 12. External evidence and what is actually ready

Production evidence supports the **boundaries**, not effortless feature completeness. Typst's [compiler architecture](https://github.com/typst/typst/blob/main/docs/dev/architecture.md) separates parsing, content, layout frames and export, retains source-span identity and tolerates erroneous syntax. Borrow that separation and explicit origin tracking; do not import its interpreter, pagination engine or `comemo` query framework into six fixed single-file formats. VS Code/JetBrains expose editor/preview and synchronized scrolling ([VS Code Markdown](https://code.visualstudio.com/docs/languages/markdown), [JetBrains Markdown settings](https://www.jetbrains.com/help/idea/markdown-reference.html)); these are credible workflows, not evidence their web engines meet mote's one-binary/native constraint.

Recent peer-reviewed structured editing research explains why preview editing is a different product contract. [Pantograph, POPL 2025](https://doi.org/10.1145/3704864) develops tree selections/typed edit propagation to reduce the difficulty of rearranging intrinsically structured programs; it does not establish an unambiguous inverse for clipped Markdown/CSV/YAML rendering or desktop IME/reader behavior. [Total Type Error Localization and Recovery with Holes, POPL 2024](https://hazel.org/papers/marking-popl24.pdf) makes error states semantically meaningful in its typed language. The transferable principle is explicit incomplete/error states, not rewriting malformed user text into holes. Mote deliberately allows arbitrary source edits and keeps lossy previews read-only. Bidirectional view editing requires a separate format-specific inverse/ambiguity and round-trip contract; it is **not** a prerequisite for native semantic rendering.

Ready mechanisms: existing bounded Engine/session publication, native Flow controls, explicit source origins/navigation, theme policy, OS virtual table/data-source APIs, OS text shaping and raster decoders. **Still unimplemented/unproved here:** full ordered rendering projections, new installed presentation identity, Grid consumer, attachment capability/accessible roles, safe resource service, data-only palette overrides, coherent native chrome/auto pane capability and rich four-RID product/reader/IME/performance gates. General bidirectional structured editing, universal render AST and a query-engine framework remain unnecessary/speculative. The important next test is not a visually impressive screenshot alone: it is a bounded inline fixture whose ordered transformed text/styles/origins survive native installation, same-version replacement and Copy on both OSes without a single source edit, accompanied by a genuinely usable native shell.
