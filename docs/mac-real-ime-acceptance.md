# Real macOS Chinese IME acceptance: hosted-runner feasibility

Status: **read-only capability probe passed on both hosted Mac architectures; no real IME conversion attempted** (2026-09-30). This is distinct from the synthetic `setMarkedText`/`unmarkText` AppKit probes, the ASCII System Events workflow, and the Windows real Microsoft Pinyin results. None of those establishes a real macOS Chinese candidate window.

## Decision question

Can the disposable GitHub-hosted macOS x64/Arm64 desktop select an **already enabled** Apple Pinyin - Simplified source, deliver real keyboard events through the OS input context to mote's focused `NSTextView`, observe live candidate/marked text without reading unrelated user content, then restore the original source and verify source bytes and selection? If any precondition is absent, retain a non-gating environmental result rather than mislabel synthetic composition as real IME acceptance.

## Cheapest discriminating probe

`tests/MacRealImeSourceProbe/Run.ps1` compiles `Inventory.m` on each hosted Mac. It **only reads** `TISCreateInputSourceList(..., true)`, current TIS source, `AXIsProcessTrusted()` and `CGPreflightScreenCaptureAccess()`. It neither calls `TISEnableInputSource` nor `TISSelectInputSource`, sends no events, requests no TCC permission and records no document content. JSON goes under `.cache/ci-inventory/<rid>/mac-real-ime-source.json`; build scratch stays under `.temp/mac-real-ime-source/<guid>`. The report includes `real_ime_tested=false` by contract. `Run.ps1` is bounded by 30 seconds for clang and 10 seconds for inventory; PowerShell parser returned **0 errors locally on Windows**. The first hosted v1 probe compiled and ran on both Macs below. The v2 read-only schema additionally records `enable_capable` for the parent and Pinyin input mode; v2 hosted behavior is pending. Presence alone is insufficient: Apple documents source identity through `kTISPropertyInputSourceID`, while Pinyin input requires actually switching source and using its candidate window. [Apple text input-source identifiers](https://developer.apple.com/documentation/appkit/nstextinputcontext/keyboardinputsources), [Apple Pinyin usage](https://support.apple.com/en-ie/guide/chinese-input-method/cimpys11836/mac), [AX trust preflight](https://developer.apple.com/documentation/applicationservices/1460720-axisprocesstrusted), [capture preflight](https://developer.apple.com/documentation/coregraphics/cgpreflightscreencaptureaccess%28%29).

GitHub labels are not stable OS-version guarantees: this repository currently uses `macos-15-intel` for x64 and `macos-latest` for Arm64, and GitHub may change the latter. Record the actual runner OS/image in the artifact rather than inferring Chinese source availability from the label. [GitHub runner-image labels](https://github.com/actions/runner-images).

### Hosted capability observation: CI run 36682437200

The [non-gating CI run](https://github.com/kleedaisuki/mote/actions/runs/36682437200) at commit `de1c40e9baea638a57d5eccabc18deced4059661` compiled and executed the read-only Objective-C inventory on **both** platforms. Artifacts were downloaded locally under `.cache/mac-real-ime-run-36682437200/{x64,arm64}/mac-real-ime-source.json`; each reports `real_ime_tested=false`. These are observed runner capabilities, **not an input test**.

| Runner | OS, current source | Pinyin - Simplified input mode | Relevant TCC preflights |
| --- | --- | --- | --- |
| `osx-x64` | macOS **15.7.9 (24G830)**; `com.apple.keylayout.ABC`; 310 installed sources | `com.apple.inputmethod.SCIM.ITABC` is installed and `select_capable=1`, but **`enabled=0`**, `selected=0`. Parent `com.apple.inputmethod.SCIM` is also disabled. | `ax_trusted=1`; `screen_capture_preflight=true`. |
| `osx-arm64` | macOS **26.6.2 (25G83)**; `com.apple.keylayout.US`; 318 installed sources | The same Pinyin mode is installed and `select_capable=1`, but **`enabled=0`**, `selected=0`; parent SCIM is disabled. | `ax_trusted=1`; `screen_capture_preflight=true`. |

**Decision:** A bare `TISSelectInputSource` on either hosted runner is not a legitimate real-IME setup, because the Pinyin mode is disabled. Apple says enabling an input *mode* additionally requires its parent method to be enabled, so selecting only `SCIM.ITABC` or assuming that an installed ID is usable is unsound. The current inventory does not record `kTISPropertyInputSourceIsEnableCapable`; no enable/select/restore sequence was attempted. A next **opt-in, disposable-runner-only** feasibility probe should first read the parent's and mode's enable-capable flags, snapshot all original enabled/selected states, then—only if legal—enable parent and mode, select Pinyin, confirm current source while the target `NSTextView` is focused, and in `finally` restore the original selected source before disabling *only* sources it enabled and re-query all states. This mutates the ephemeral runner's user-session input preferences temporarily; it is **not process-local** and must never run on a developer or user machine without explicit consent. The safer alternative is a dedicated Mac test account with Pinyin pre-enabled or a supervised human test. [Apple Text Input Source Services reference](https://leopard-adc.pepas.com/documentation/TextFonts/Reference/TextInputSourcesReference/TextInputSourcesReference.pdf), [Apple input-mode management note](https://developer.apple.com/library/archive/qa/qa1810/_index.html).

## Conditional real-input experiment, not yet implemented or passed

Only if an **enabled and select-capable** Pinyin source is present, execute a separate non-gating runner probe on a disposable fixture and desktop session:

1. Save the exact current TIS source ID and its selected/enable state; choose only the already-enabled Pinyin source via `TISSelectInputSource` or the target `NSTextInputContext.selectedKeyboardInputSource`. Never enable a source, edit `com.apple.HIToolbox` preferences, call `tccutil`, or persist a system preference. Put source restoration in `finally` and re-query it after mote closes. A disposable runner reduces risk but does not make restoration optional.
2. Launch the **published lone Mach-O** for the correct RID, with a repo-local UTF-8 fixture such as `a\n你好`; use the same PID and AX-focused-`NSTextView` readiness checks already in `tests/NativeMacExternalWorkflow.ps1`. Capture immutable pre-input source version (if an explicitly exposed test hook exists), global selection and full-document AX length/hash before sending input. Do not infer `Document.Version` from disk hash or AX value if no hook exists.
3. Send distinct hardware-keycode events for `n i h a o`, rather than `CGEventKeyboardSetUnicodeString`, AppleScript `keystroke "nihao"`, paste, direct `insertText:`, or synthetic `setMarkedText:`. Apple documents that Quartz keyboard events enter the window-server event path and `NSTextInputContext` handles input for its active client; nevertheless, **events alone still do not prove a real IME**. Confirm the selected Pinyin source again while mote owns foreground and find a live candidate/marked-text observation. An app-only screen crop may not contain an OS-owned popup, and screen capture may be denied; in that case use a narrowly targeted AX candidate window or stop as inconclusive, never take a full desktop screenshot. [Quartz event path](https://developer.apple.com/documentation/coregraphics/cgevent), [event posting](https://developer.apple.com/documentation/coregraphics/cgevent/post%28tap%3A%29), [AppKit input context](https://developer.apple.com/documentation/appkit/nstextinputcontext).
4. In **Insert**, choose visible candidate `你好`, save, close, reopen in a fresh process and compare exact UTF-8 bytes (`610AE4BDA0E5A5BD` for `a\n你好`) and selection. In **Cancel**, use Escape during the visible candidate, then save/reopen and require exact original bytes. In **same-text replacement**, select a global range spanning off-host text before conversion, and require only the chosen candidate—not a duplicate or stranded prefix. Record source range, version/edit count only when observable through an explicit privacy-safe hook; otherwise mark them unavailable. Do not log document content, filenames outside the fixture, or candidate text from other apps. Distinguish marked preedit from committed source using an in-process hashed event trace if the external APIs cannot do so.

**Release gate:** no result may be called a real macOS IME pass merely because Pinyin is installed, selected, an event was posted, an `AXTextArea` was focused, `setMarkedText:` synthetic tests passed, or final bytes coincidentally match. Require an actual OS candidate/marked-text observation plus exact commit/cancel Save/reopen behavior and source-selection restoration. If the hosted runner lacks an enabled Pinyin source, TCC blocks the event/candidate observation, or foreground cannot be established without global desktop interaction, use a dedicated disposable self-hosted Mac or a supervised physical-keyboard Mac session with the existing `.temp/ime-probes/macos-input-source.sh` as the safe alternative.
