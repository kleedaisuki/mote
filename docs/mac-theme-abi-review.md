# macOS live-appearance change: independent ABI and state review

Date: 2026-09-30. Scope: uncommitted `MacEditorShell`, `MacTextInputIsland`, shared controller/contracts, and the new controller tests. This was source review on Windows, **not** an executed macOS or Native AOT ABI test. No production files or tests were changed by this review.

## Disposition

No demonstrated source-level blocking defect found in the requested macOS path. The important remaining uncertainty is target-host validation, not a claim that C# compilation proves Objective-C callback correctness. Local Release compile and the 409-test suite are recorded in `tests/VALIDATION.md`; they exercise fake shell/controller logic but neither AppKit callbacks nor both Mach-O architectures.

| Concern | Assessment and evidence | Remaining acceptance probe |
| --- | --- | --- |
| Runtime subclass/super dispatch | `MacEditorShell.cs:1352-1361,1415-1427` subclasses `NSTextView`; `MacTextInputIsland.cs:1404-1407,1474-1486` subclasses `NSView`. Both register a no-argument `v@:` IMP with a Cdecl function pointer and call `objc_msgSendSuper` using a two-pointer `objc_super` layout and the **immediate superclass**, not the subclass itself. That matches Apple's runtime description of lookup starting at the supplied superclass. It is also consistent with the existing three-argument super call for canvas text input. Managed exceptions are caught at each unmanaged boundary. This is ABI reasoning, not target-host evidence. | Publish/run both osx-arm64 and osx-x64 Native AOT; trigger light→dark→light while each editor mode is visible. Confirm the callback fires, super dispatch returns, and input/painting continue. An `NSView` subclass callback should be checked separately from `NSTextView`. |
| Appearance classification and object ownership | `MacEditorShell.cs:125-159` obtains the editor's `effectiveAppearance`, asks `bestMatchFromAppearancesWithNames:` for the standard Aqua/Dark Aqua names, and uses the match before a name fallback. Apple's API explicitly returns the closest supported name. `ObjC.String` creates autoreleased strings, the temporary `NSMutableArray` is explicitly released, and the local `NSAutoreleasePool` is released in `finally`; no observed over-release or escaped autoreleased pointer. `NSAppearanceNameAqua`/`NSAppearanceNameDarkAqua` are framework-defined NSString values; literal equality should still be verified on a host rather than assumed from a C# build. | Log only matched appearance **name**, not document text, under system, explicit light/dark, and (if available) vibrant/high-contrast appearances. Confirm correct polarity. |
| Default vs canvas appearance source | `PrefersDark` queries the actual editor view when it exists rather than `NSApplication`; callbacks are attached to the editable default `NSTextView` subclass and canvas `NSView`. Notification readiness suppresses construction noise, then `Shown` performs one final observation. This accounts for window/view inheritance and startup transitions. | Test per-window appearance overrides and real system switching; the default and canvas view must each yield the displayed polarity. |
| Composition-settled ordering | `ObserveCompositionState` gates on `HasPendingComposition` (canvas) or marked/dirty state (default), and timer path invokes `CommitPendingText`/`CommitComposition` before raising `CompositionSettled`. Canvas `CommitFinal` clears dirty state and runs the source edit callback before the shell's settled observation. The controller then applies only its latest pending policy when `IsTextComposing` is false. No source/selection mutation is intentionally part of theme application. | Real Chinese/Japanese IME commit **and cancellation**, during both theme directions, on both modes. Assert bytes/version/undo and native selected range before and after; synthetic controller events are insufficient. |
| Color-only changes | Both shell and canvas compare typography/spacing and avoid host font rebuild/`PlaceHost` for same-font palette transitions. `MacEditorShell.SetPreview` recolors spans even when `updateFonts` is false; changed preview text forces font work. This matches the intended no-layout transition. | Visual screenshot/selection contrast check; observe no caret or viewport jump for palette-only transition. |
| Stamped analysis and preview privacy | `NativeDocumentStamp` includes generation and version. Mac default analysis accepts only the current document stamp; canvas accepts only the current binding stamp. A new default stamp/page or a different canvas snapshot clears cached analysis and native preview immediately; stale async analysis is rejected. Failure messages/status notices are generic rather than document-derived. | On target host, switch documents/pages/formats while analysis is pending and verify no previous-document preview/token flash, including after an analysis failure. |

### Risk to keep visible (non-blocking, conditional)

`MacEditorShell.SetTheme` writes some native paint roles before `ApplyAnalysis`; a later AppKit/CoreText failure can leave a partially painted UI until the controller's best-effort rollback. `NativeEditorController.ApplyPendingTheme` retains canonical source state and posts a generic nonmodal notice if rollback also fails. This is the stated recovery model, not atomic native rendering. A fault-injection test of a mid-apply failure on a macOS host would sharpen confidence, but there is no demonstrated user-visible failure path from the current source alone.
