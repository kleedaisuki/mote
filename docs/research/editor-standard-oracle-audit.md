# Editor standards and acceptance-oracle audit

Date: 2026-10-02. Status: independent standards review and proposed protocol; **not a production change, acceptance run, or authorization to relax the active goal**.

## Scope and decision

Reviewed repository documents and current source for native source reference fixtures, capability probe, production binding/controller contracts, launch profile selection, native startup and ordinary large-JSON acceptance, artifact classification and workflow supervision. Reused existing validation results rather than rebuilding or rerunning them. Current working tree contains concurrent production integration changes; source existence is not published-image qualification. No production, test, benchmark or workflow was changed and no GUI/process experiment was launched for this audit.

The central distinction is:

```
Product obligation -> representation-independent behavioral oracle
Implementation candidate -> representation-specific capability experiment
Observer implementation -> versioned, bounded evidence protocol
```

An experiment's complete source replica, complete readback, all-token native publication, fixture sizes or specific control tree must not become a universal product requirement merely because the experiment passed. Conversely, a cheaper oracle must not discard exact persistence, input settlement, semantic completeness, global navigation or previously required capacity.

The inspected documents generally already make these distinctions correctly. The material risk is **reusing old observers or promoting limited capability evidence**, not a demonstrated current release falsely claiming completeness. The explicit `--native-source` candidate remains opt-in in `EditorPresentationProfile.cs`; ordinary startup still selects Continuous.

## 2. Concrete evidence and prioritization

### High importance: observer coupling can bias replacement decisions

`benchmarks/NativeStartup/README.md` explicitly requires a RichEdit input island below `MoteInteractiveCanvas`, checks its prefix and caps its size at 16,384. The ordinary JSON driver's source-readiness logic similarly uses `0 < length <= 16384` plus expected prefix. Those are useful tests of the *current bounded input island*, not natural invariants of a source editor. The current full-body product candidate uses `RICHEDIT50W` as the sole painter, with full source resident. Reusing an unchanged driver for a replacement would test the old tree and storage representation instead of exact global editing.

**Correction protocol:** preserve the historical route and result name. Supply the chosen profile/adapter identity before launch, not by guessing after a failure. For each reviewed adapter, discover an owned current source object and certify (a) document identity and global source extent, (b) a bounded exact source range at the intended edit offset, (c) selection readback, (d) one admitted action with independently expected resulting source/version, (e) exact Save and fresh-process reopen. The observer may extract a bounded range even when the underlying document is complete. Record adapter-specific residency separately. A successful alternative must not falsely claim the old bounded-island invariant.

Confidence: high from inspected contract and source; **no failed replacement run was performed**.

### High importance: full semantics and eager style publication are independent

The reference probe's `Publish` does a full policy call, projects all tokens, publishes all foreground attributes and then checks conservation. Current product `NativeSourceSemantics` carries completeness/coverage and canonical tokens; `WindowsEditorShell.Source.cs` applies bounded decoration. The Windows adapter document states an 8192-unit viewport-derived interest and at most 128 foreground calls per turn. It also explicitly admits that the 8192 interval is **not complete viewport coverage**.

Do not describe bounded publication alone as solving the visible-decoration contract: a long wrapped paragraph can expose more than that interest. The necessary requirement is current decoration over actual visible content, or explicitly neutral pending presentation. A per-turn budget is implementation scheduling, not permission to leave visible text indefinitely wrong. Nor does viewport token filtering establish global YAML/TOML/Markdown dependency correctness.

**Revised oracle:** at each tested visible interval, capture source/version/theme/viewport identity; compare published current token/diagnostic meaning with the relevant complete reference on ordinary six-format cases; independently inspect native attribute ranges at token/default boundaries and after moving into formerly offscreen text. Change an offscreen dependency affecting the viewport, then verify invalidation. Require source/selection/composition/scroll/history conservation. Report semantic completion and visible-attribute completion as separate endpoints. Full offscreen attribute publication is not required before editability.

Confidence: high for separation and stated coverage limit; native rendering outcome remains unexecuted here.

### Medium importance: full residency and single painter are not one conclusion

`ordinary-editing-locus.md` recommends an inexpensive full-resident diagnostic but explicitly limits promotion and proposes later continuous native virtualization. That distinction is sound. The resulting product candidate's installation/binding APIs are intentionally whole-source. This makes full residency an implementation invariant today, **not a proven optimum for all supported sizes**. A single visible editing locus is a useful behavior goal; it does not logically choose RichEdit/TextKit, AOT/JIT, full string readback or a permanent replica.

The 6827cd1a hosted component observations recorded in the goal checklist include Windows dense 512 KiB JSON publication at 5.2–10.3 seconds and novel import/history reimport at 3.8–4.9 seconds. These identify actual reference-path costs; they do not benchmark current range-based product Undo/Redo, which avoids whole reimport, and do not prove a replacement toolkit is faster. Mac attribute-update improvement under the same delivery model is evidence against treating packaging as the root cause.

**Revised design gate:** retain candidate-specific exact import tests. Before promotion, run equivalent ordinary interaction and existing capacity lanes with measured stage attribution. If full residency fails, change the binding model deliberately, maintaining global source/selection/history/IME/accessibility contracts. Do not hide a size threshold switching users back to ribbons/pages. Do not reject a reviewed virtualized design merely because it does not implement a whole-string interface built for the experiment.

### Medium importance: capability and release readiness cannot be collapsed

`native-codec-source-workflow.md` and `goal-checklist.md` already correctly label the reference experiment and fresh-Document reopen. The ordinary JSON documents preserve actual exit codes and non-gating failures. Retain that calibration in the integrated research answer. Four-RID complete reference runs, 3508 managed tests, normal trace terminal and bounded foreground witnesses are valuable component evidence; none supplies physical input-to-visible latency, real CJK composition, assistive-technology behavior or statistical Save reliability.

## 3. Exact proposed product protocol (no execution in this audit)

1. **Freeze provenance:** source/dirty manifest, package inventory and executable/library/runtime hashes; RID/OS/display/observer versions and isolated repo-local home. Hash/generate synthetic fixtures outside timers. Predeclare whether the tested route is ordinary or explicit candidate. Retain current external contracts until a separate migration decision.
2. **Baseline discovery:** own exact process/window/provider, current global document identity/extent, source-backed selection and bounded source range. Window title or control readiness is insufficient. Record focus/first-responder state separately.
3. **Ordinary functional matrix:** supported six formats with valid and recovery/error cases, representative CJK/mixed scripts/newline/emoji/grapheme data, ordinary sub-1 MiB tasks and few-MiB reading; retain existing large/long-line regressions in a separate lane. Fixed sizes are strata, not universal claims.
4. **Input and history:** one non-idempotent attempt per scripted edit; start/middle/end selection and replacement, burst settlement, Undo/Redo and cancelled composition. Real CJK IME commit/cancel and command-during-composition must use the actual input route. Every final accepted edit appears once; provisional input is not lost; failed settlement refuses destructive commands. Stale document/version/view events are challenged independently. Direct native messages remain a separate diagnostic input class.
5. **Semantics and decoration:** compare stable complete claimed results with independent reference/conformance fixtures, preserving explicit partial/unknown status. Verify visible range/theme changes and offscreen dependencies without demanding eager styling of the entire file. Native returned attributes, draw callback return and observed pixels are distinct witnesses.
6. **Persistence:** external expected bytes/encoding/BOM/newlines derived before interaction; unchanged original fixture until authorized Save; exact saved SHA; original child normal exit; distinct fresh GUI reopen with exact source witnesses and clean state; reopened child normal exit. On failed Save preserve original and retain recovery ownership. Observer hashing must not keep a handle that obstructs replacement.
7. **Endpoints and failure:** independently report launch-to-interactive, semantic-current, input-to-canonical, input-to-visible and scroll endpoints. Preserve raw successful/failed/cancelled/censored counts. No automatic retry of non-idempotent input, silent fallback profile, killed-process pass, or post-hoc selective result pooling.
8. **Readiness verdict:** a capability sample answers only whether that scoped path worked. Performance thresholds require agreed hardware/workload and adequate repetitions; none is invented here. Release acceptance needs separately completed UX/IME/accessibility/reliability lanes, not job color.

The common oracle is behavioral. Platform adapters are allowed to differ in discovery, text storage and layout, but not in exact admitted source, safe persistence or promised global operations.

## 4. External reality: production facilities and research

- Microsoft's [TextPatternRange.GetText](https://learn.microsoft.com/en-us/dotnet/api/system.windows.automation.text.textpatternrange.gettext?view=windowsdesktop-10.0) explicitly supports bounded text extraction. This supports bounded observer readback of requested source ranges; it does **not** prove the current provider's canonical newline mapping or global accessibility geometry.
- Apple's [Meet TextKit 2](https://developer.apple.com/videos/play/wwdc2021/10061/) describes noncontiguous viewport-based layout and warns that offscreen layout information may be inaccurate until ensured. Thus correct native architecture need not eagerly lay out every offscreen glyph. It remains necessary to qualify required offscreen geometry operations and input/accessibility integration; the talk is not proof that mote's current bridge provides them.
- Peer-reviewed [A Stable Lossless Syntax Tree for Real-Time Collaborative Programming, ECOOP 2026](https://drops.dagstuhl.de/storage/00lipics/lipics-vol372-ecoop2026/html/LIPIcs.ECOOP.2026.5/LIPIcs.ECOOP.2026.5.html) separately evaluates byte-identical replay, determinism/identity and latency in a two-language prototype. The useful research signal is to treat preservation and operational responsiveness as separately checked properties. It does not validate mote, six formats, native IME or distributed transport; a lossless structural model is an architectural alternative, not permission to infer semantic completeness from a parser name.

These sources support separating behavioral obligations from representation costs. They do not independently establish numerical latency limits or user prevalence.
