# Published native codec and source-capability CI integration

This adds three steps to the existing four-RID Native AOT matrix. It introduces
no job, application flag, supervisor framework, GUI retry or delivery payload.
All preceding steps, original Grid pins, strict one-binary contract and AppKit
Flow gates remain unchanged. The two probes are independent: a codec failure does
not suppress the separately non-gating source experiment when an inventoried
published executable exists.

## Two different acceptance boundaries

| Probe | Process deadline | CI policy | Positive evidence |
| --- | --- | --- | --- |
| `--check-native-encoding` | 60 seconds | Blocking tiny published-image correctness check; no GUI | Actual numeric exit 0, exact `mote-native-encoding-ready`, closed report, correct native architecture and all seven ordered labels |
| `--check-native-source-capability` | 120 seconds | Non-gating native experiment, not default profile/product acceptance | Actual numeric exit 0, current binary identity, runtime architecture, final `probe/complete`, three fixtures with exact Save and fresh-document-reopen terminals, matched timed phases; separate trace drain witness |

The codec labels are exactly:
`Gbk_exact_save`, `Gbk_strict_encode_protection`, `Gb18030_exact_save`,
`Big5_exact_save`, `Big5_strict_encode_protection`, `default_utf8_refusal`,
`unicode_bom_conflict_and_exact_save`.
Report schema/status/error-kind/key set and ordered string checks are validated;
bool schema values, wrong architecture, missing labels and an absent marker fail.
These are production-engine operations on tiny generated bytes, not platform GUI
or broad legacy-encoding corpus certification. See
[the explicit encoding contract](explicit-open-encoding.md).

The native source experiment has **no stdout success marker**. Its final global
completion row retains the last fixture label `dense-json`; the integration
correctly checks `phase=probe,state=complete`, not `fixture=probe`. Each of
`mixed-text`, `novel-text` and `dense-json` must retain one `saved-bytes/exact` and
one `fresh-document-reopen/completed`. Every entered timed phase must have its
matching terminal in sequence. A failed phase, partial final line, unpaired
phase, missing fixture or incorrect executable hash remains unknown, not passed.
This is fresh `Document.OpenAsync`, **not** a child-process/native GUI reopening.
See [the source experiment contract](native-source-capability-probe.md).

The source probe's pre-shutdown telemetry-health note is distinct from post-exit
trace evidence. The wrapper separately inventories the owned trace rotations,
requires complete JSONL framing, one `mote.session/success` and no observed
`telemetry.dropped`. `trace_drain_witness=observed` means these narrow terminal
facts were seen, **not** complete transport, strict trace-schema/graph validation
or absence certification. Raw rotations remain available for the existing strict
readers and subsequent hosted audit. Missing/invalid trace evidence prevents an
overall observed source result even if the phase report itself completed.

## One small shared execution block

The workflow reuses one literal through a YAML anchor/alias, an officially
[supported Actions mechanism](https://docs.github.com/en/actions/reference/workflows-and-actions/reusing-workflow-configurations).
Both steps use the same checked source; only the closed `PROBE_KIND` environment
value differs. This avoids duplicating a new process framework or the larger
Windows Grid job-object bridge for childless probes.

Admission requires GitHub-hosted Windows/macOS identity. The repository-contained
artifact directory must be fresh and all existing ancestors non-reparse. The
existing single-executable inventory is checked and the actual binary SHA is
recorded before and after. No local override or hosted-identity impersonation is
provided. `MOTE_HOME` points to owned isolation; the source experiment explicitly
owns its additional `probe/mote-home` through the existing configuration loader.
No real user home or settings are modified.

`ProcessStartInfo` launches the exact published binary once without shell
interpretation, with `CreateNoWindow` for helper console behavior and no product
activation/focus repair. Async stream copies write stdout/stderr prefixes directly
into CreateNew files while the process runs. They cannot fill a pipe while the
parent is waiting for exit, and a censored attempt keeps already copied bytes.

After the process deadline, **one shared 10-second cleanup stopwatch** budgets
the exact owned process exit wait and both stdout/stderr drain observations.
There is no unbounded `ReadToEnd` await, second cleanup deadline, replacement
sample, foreign/global PID kill or recursive artifact deletion. Only an actual
confirmed process exit supplies a numeric exit code. Cancellation/disposal faults
keep a fixed error category and unknown result rather than becoming healthy.
Incomplete stream copies are not called complete merely because handles were
disposed. PowerShell scriptblocks are not scheduled on task threads without a
runspace.

Both production probe contracts create **no child process**. This wrapper uses
the established exact-process launch/kill pattern rather than claiming a Windows
job-object or macOS descendant guarantee. `descendant_boundary=not_certified` is
explicit on both platforms. A future probe which spawns children requires a new
ownership review; these current controls are not a reusable process-tree promise.
Forced kill or unproven cleanup is censored, never normal. Failure before launch
stays unobserved. Diagnostics neither select a new default editor nor certify
physical paint, real typing, IME, accessibility speech, presentation or product
readiness.

## Retention and pre-hosted verification

Actions always uploads, including hidden files, for 14 days:

- `.cache/ci-inventory/<rid>/encoding-runtime/**`
- `.cache/ci-inventory/<rid>/source-capability/**`

The trees contain supervisor facts, raw stdout/stderr, probe reports, generated
fixtures, isolated homes and enabled trace rotations. Files use exclusive
creation; previous evidence is never overwritten/deleted. The non-gating step's
green job conclusion is not evidence qualification.

On 2026-10-01, **28 validation-only classification fixtures passed**: simulated
metadata for both probes and all four RID labels, and negative marker/schema/
architecture/label/exit/cleanup/stream/failure/phase/fixture/binary/trace-framing/
drop/session cases. The fixture code invokes only the report-validation section,
not admission, process launch, native entry points or GUI. An in-memory async
stream-copy and bounded `Task.WaitAll` check verified the chosen .NET overloads.
Four affected follow-up cases checked closed cleanup, process-evidence and
image-identity error categories; these failures cannot leave an outward null
error category or reveal an arbitrary exception message. The preceding 28
classification cases and previously qualified model/native tests were not rerun
for that metadata-only correction.
YAML parsing confirms anchor/alias literals are equal; removing exactly the three
added steps yields the entire prior workflow structure unchanged. The shared
PowerShell block passes AST parsing. Artifacts and reproducible validation-only
scripts are under `.cache/validation/native-codec-source-workflow/`.

Already qualified model/build tests were not repeated. These portable/static
checks do **not** supply published-image codec or native GUI evidence. All four
actual Native AOT runtime results remain pending the reviewed coordinator push.
