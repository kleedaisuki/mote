# Native input island for the continuous canvas

Status: **proposed integration contract, not implemented**, 2026-09-29. This is a focused sequel to [continuous virtual editor design](virtual-editor-design.md), not a replacement for the [current native input/AX audit](native-input-accessibility.md). It specifies how a bounded OS text control might supply editing and IME services to an engine-backed canvas without becoming a second document. The present `Mote.Native` still edits a 64 Ki-unit RichEdit/NSTextView page with 8 Ki units of slack. CI has passed Windows real-control and macOS external-keyboard small-file save/reopen workflows, plus read-only offscreen canvas probes; **no real CJK IME, interactive canvas, or global accessibility provider has passed** ([validation record](../tests/VALIDATION.md), [integrated CI](https://github.com/kleedaisuki/mote/actions/runs/36553927870)).

## Decision and the hard boundary

The canvas and `ContinuousViewport` own source-backed geometry, paint, global caret/selection, and scroll. `Document`/`TextSnapshot` remain the only committed text and I/O authority. The native **input island** is a physically visible, bounded, focusable RichEdit child window or `NSTextView` over the active caret fragment; it owns provisional marked text, local selection, native candidate geometry, and short-lived OS input state. It must never contain a whole-file hidden mirror. Start with a **4-16 Ki UTF-16 source-window hypothesis**, bounded by safe grapheme/CRLF seams and adjusted only by measured IME context needs. This is an implementation tuning range, not a user-visible truncation rule. A larger paste or selection uses a global source replacement, not an enlarged mirror.

Run the new path behind an opt-in `--canvas-experimental` switch while existing `INativeEditorShell` page mode remains the default. This preserves established open/edit/save/undo/shortcut behavior during migration. Do not remove page mode until both OSes pass the real-input and accessibility gates below. Strict one-binary packaging remains unchanged: RichEdit and AppKit are OS facilities, not shipped sidecars.

```text
Document generation G, TextSnapshot version V  (only committed text)
           | bounded source slice and absolute selection
           v
CanvasController: global selection + ContinuousViewport + semantic overlay
           | caret rectangle and local projection
           v
Native island: RichEdit HWND / NSTextView first responder
           | provisional marked text (not saved or parsed)
           | one versioned CanvasCommittedEdit on final commit
           v
CanvasController validates (G,V), applies Document.TextChange once
```

### One transaction model, including off-island selections

An `IslandBinding` contains the immutable `TextSnapshot`, **document generation** (incremented whenever New/Open replaces the document), `BaseVersion`, bounded absolute source interval, the original source slice, the local `NativeTextProjection`/platform offset map, global selection's replacement span, and a monotonic binding nonce. The view owns `anchor/active` in **absolute source UTF-16**, including reversed selection and affinity; the island owns only local native offsets. A composition captures its replacement span at start and freezes that span until commit/cancel. If global selection covers 20 MiB, the island still binds a small caret-local context, with local selection possibly collapsed; the eventual `TextChange` deletes the **global** selected range once and inserts the committed candidate. Cancel leaves both document and global selection unchanged. Any native reconversion request targeting outside the bound source context must be detected and handled by an explicit expansion/fallback decision, **not** clipped into a wrong absolute edit.

The event sent upward is a typed value, not whole page text:

```csharp
/// One final OS-input transaction against a specific document and snapshot.
internal readonly record struct CanvasCommittedEdit(
    long DocumentGeneration, long BaseVersion, long BindingNonce,
    TextChange Change, int ActiveSourceOffset);
```

`Change` uses absolute source offsets. The controller alone calls `Document.Apply`, updates engine undo/dirty state, transforms global selection and viewport anchor, and schedules format analysis. Accept a commit **only if** generation, version, and nonce match the active binding; do not guess a new offset after an asynchronous Open/Format result. If a stale native event arrives, suppress it, preserve the current engine document, and rebind or show an actionable error. A duplicate final notification for the same nonce/native revision is idempotently ignored. A no-op composition cancel emits no `CanvasCommittedEdit` and advances no engine version. Ordinary non-IME keystrokes may each be one transaction; a whole IME conversion should be one undoable transaction unless target-OS behavior proves a different grouping necessary.

The binding's source/native map must obey the existing tested projection law `Project(Apply(source, Difference(nativeDisplay))) == editedDisplay`, including CR/LF/CRLF seams. Windows additionally has RichEdit's internal single-CR position space (`RichEditOffsetMap`) and external `GT_USECRLF` text; neither may leak into global offsets. Never use `NSTextView`/RichEdit's local selection as a substitute for a global selection crossing the bound interval. The canvas paints that selection; Ctrl/Cmd+A, Copy/Cut, Find, Go To Line, Undo and Redo remain controller commands. The island can receive navigation keys, but a move beyond its bound interval is a **global** move followed by a safe rebind, never a native page flip.

## Composition state and command ordering

| State | Engine/view invariant | Allowed operations | Exit |
| --- | --- | --- | --- |
| `Unbound` | No native control may report an edit. | Create/reposition host and bind source slice. | `Ready` after text, map, selection and focus agree. |
| `Ready(G,V,N)` | Native display projects the binding's source window; no marked text. | Normal key/paste commits, global navigation/rebind, color-only canvas repaint. | `Composing` on OS begin/marked text; `Settling` for a command requiring reconciliation. |
| `Composing(G,V,N)` | Provisional text exists only in OS control; the engine stays at `V`. Replacement span, source window and typography are frozen. | Native candidate update/cancel/commit; canvas may repaint committed surroundings. Scroll may move the **same** host physically but must keep caret/candidate visible. | `Settling` only after OS reports composition ended or user command invokes a tested settle path. |
| `Settling(G,V,N)` | No document swap, Save, formatting result, rebase, or style replacement may run yet. | Read final native text/selection after OS callbacks; compare to frozen binding. | Emit at most one committed edit (or no-op cancel), then `Ready` with new binding; or visible veto/fault. |
| `Faulted` | Engine snapshot remains authoritative; no speculative native text is saved. | Show error, discard/recreate island **only after** composition is safely ended; offer page-mode rollback when feasible. | `Ready` only after projection equality is re-established. |

All state transitions run on the OS UI thread. Input events may be reentrant; use a narrow transaction guard rather than holding `Document` locks across native callbacks. A command with I/O, global selected-text access, or a caret/document rebind calls `TrySettleComposition` first. **Save/Open/Close/Format/Undo/Redo/Copy/Cut/Find/Go To/Select All and completion of an earlier asynchronous Open/Format must either synchronously reach a validated `Ready` state or veto/defer without changing the file/document.** Do not call `Document.SaveAsync` while marked text is visible. An async result carries the generation/version at launch; before publishing it, recheck those values, settle the current island, then recheck again. Theme **colors** can update canvas while composing, but font/DPI/wrap changes, text restyling and rebinding wait until settlement. Format-analysis results for old committed `V` can paint outside the island if they still match `V`; they must not overwrite marked text or mutate island storage. After commit to `V+1`, all stale `V` overlays are discarded and analysis is rescheduled.

Do not rely on a single timer or on `WM_IME_ENDCOMPOSITION` alone as a universal commit signal. For an end notification, queue a one-shot reconciliation after the current native callback burst; if a following unrelated key arrives first, reconcile **before** dispatching it so the key cannot be merged with the IME transaction. While a settle is pending, block duplicate commit emission by nonce/revision. Test event permutations with a fake island and then log real IMEs before fixing the final ordering policy. A repeated or late notification must not replay a candidate.

## Windows RichEdit event contract

Keep a real, enabled `RICHEDIT50W` child HWND as keyboard focus target at the canvas caret, not an offscreen 1×1 hidden control. The OS RichEdit supplies editing/IME/TSF behavior and native candidate placement; the canvas suppresses duplicate glyphs beneath the visible island. RichEdit's own caret rectangle should agree with the canvas caret at the bound location. Microsoft's RichEdit documentation describes built-in candidate-position and document-feed behavior, but **does not prove** that moving/repositioning a tiny host mid-composition preserves it for mote ([RichEdit capabilities](https://learn.microsoft.com/en-us/windows/win32/controls/about-rich-edit-controls)). `IMC_SETCANDIDATEPOS` is documented for apps drawing composition themselves, so do not apply it reflexively to a RichEdit-hosted IME ([Microsoft candidate-position contract](https://learn.microsoft.com/en-us/windows/win32/intl/imc-setcandidatepos)).

| Observable event | Proposed adapter action | What must be measured |
| --- | --- | --- |
| `WM_IME_STARTCOMPOSITION` and/or RichEdit `EN_STARTCOMPOSITION` | Latch `Composing` **before** allowing page/binding/style replacement; capture global replacement span and bound version. Forward the native event to RichEdit. | `EN_STARTCOMPOSITION` also covers TSF by Microsoft contract; confirm which messages actually arrive for Microsoft Pinyin, Japanese and Korean IMEs, and their order ([Microsoft start notification](https://learn.microsoft.com/en-us/windows/win32/controls/en-startcomposition)). |
| `EN_CHANGE` / `EN_SELCHANGE` | In `Ready`, read bounded native text/selection and produce a localized final edit. In `Composing`, treat them as provisional, not engine mutations. | Query `EM_GETLANGOPTIONS`: Microsoft's default `IMF_IMEALWAYSSENDNOTIFY=0` suppresses these notifications during the undetermined state, but settings and IMEs may differ; do not assume suppression ([Microsoft IME options](https://learn.microsoft.com/en-us/windows/win32/controls/em-getlangoptions), [EN_CHANGE](https://learn.microsoft.com/en-us/windows/win32/controls/en-change)). |
| `WM_IME_ENDCOMPOSITION` and/or `EN_ENDCOMPOSITION` | After native forwarding, enter `Settling`; reconcile final control text once after notifications reach a stable point. Difference-from-baseline zero means cancel/no-op, **not** proof that a particular key was Escape. | `WM_IME_ENDCOMPOSITION` only says composition ended; `EN_ENDCOMPOSITION` covers IME/TSF and may include condition data. Verify final `EN_CHANGE` ordering and result/cancel behavior; do not equate end with commit ([Microsoft end notification](https://learn.microsoft.com/en-us/windows/win32/controls/en-endcomposition), [WM_IME_ENDCOMPOSITION](https://learn.microsoft.com/en-us/windows/win32/intl/wm-ime-endcomposition)). |
| Save/Open/Close while composing | Initially **veto visibly** if RichEdit cannot expose a reliable synchronous completion; never synthesize `WM_IME_*` to force a commit. If a documented/tested completion path is later found, settle and then execute. | Existing `WindowsEditorShell.CommitPendingText()` currently returns false during `_imeComposing`; real Pinyin was **not** validated by the local ASCII `nihao ` SendInput negative probe ([input audit](native-input-accessibility.md)). |

The parent receives RichEdit composition notifications through its native window path (`WM_NOTIFY` for `EN_STARTCOMPOSITION`/`EN_ENDCOMPOSITION`, `WM_COMMAND` for `EN_CHANGE`); inspect source/native headers during implementation rather than assuming all notifications share one path. Keep OS event-mask settings and language options observable in privacy-safe traces. Do **not** enable `ES_NOIME` or `ES_SELFIME` merely to simplify the adapter; the latter asks the application to handle all IME operations ([RichEdit styles](https://learn.microsoft.com/en-us/windows/win32/controls/rich-edit-control-styles)). Do not ship a hand-written TSF text store until the real-host design has failed a discriminating probe; Microsoft's [text-store contract](https://learn.microsoft.com/en-us/windows/win32/tsf/text-stores) is much larger than a key callback. Native AOT COM binding for future UIA/DirectWrite must be explicit AOT-compatible interop, not built-in runtime COM ([Native AOT COM warning](https://learn.microsoft.com/en-us/dotnet/core/deploying/native-aot/warnings/il3052)).

One important cancellation subtlety: Microsoft's `IMF_IMECANCELCOMPLETE` option says that **when clear (the documented default), cancel may use the composition string as the result rather than discard it** ([language options](https://learn.microsoft.com/en-us/windows/win32/controls/em-getlangoptions)). Therefore `Esc` and `WM_IME_ENDCOMPOSITION` do not themselves prove “no edit.” The invariant is conditional on the **final control text**: unchanged means no engine version, changed means one committed replacement unless a separately tested explicit discard operation restores the baseline. Do not flip this option without testing real IME expectations, reconversion and existing userspace behavior.

## macOS NSTextView event contract

Keep a real `NSTextView` in the window; make it first responder via `NSWindow.makeFirstResponder:`, **not** by calling `becomeFirstResponder` directly ([Apple NSTextView](https://developer.apple.com/documentation/appkit/nstextview)). Its local storage is bounded context, and the active composition is native-marked text. Apple's `NSTextInputClient` methods distinguish `setMarkedText:selectedRange:replacementRange:` from `insertText:replacementRange:` and expose `hasMarkedText`/`markedRange`; replacement ranges are **local to that text client**, not engine offsets ([Apple marked text](https://developer.apple.com/documentation/appkit/nstextinputclient/setmarkedtext%28_%3Aselectedrange%3Areplacementrange%3A%29), [Apple insertion](https://developer.apple.com/documentation/appkit/nstextinputclient/inserttext%28_%3Areplacementrange%3A%29)). The island maps them through its bound source window, except that an already captured global selection may be the actual engine replacement span.

| Observable callback/state | Proposed adapter action | What must be measured |
| --- | --- | --- |
| `hasMarkedText == true`, `markedRange`, `textDidChange:` | Enter/retain `Composing`; keep text and selection inside NSTextView. Do not publish `textDidChange:` as an engine edit while marked. | `textDidChange:` is a general text-change notification, not a finalization oracle ([Apple notification semantics](https://developer.apple.com/documentation/appkit/nstextview/didchangetext%28%29)). Record callback order for real Pinyin/Japanese/Korean input. |
| `hasMarkedText` becomes false after `insertText:`/`unmarkText` or delegate callback | Enter `Settling` and reconcile exact final bounded string once; later identical callbacks are echoes. `unmarkText` is a candidate settle mechanism, **not an automatic guarantee** that user-intended text was committed correctly. | Current shell already withholds marked text and calls `unmarkText` for commands; an in-process marked-`中` test passed Save As/New/reopen, but no real IME candidate test did. Verify keyboard and conversion cancellation separately. |
| Viewport scroll/scale moves the active host | Reposition the same NSTextView without changing its string/marked range; keep candidate/caret visible. Invalidate cached text-input coordinates after geometry changes. | `firstRect(forCharacterRange:actualRange:)` must return a **screen-coordinate** rectangle and may adjust to a grapheme/line fragment; `NSTextInputContext.invalidateCharacterCoordinates()` tells the input system to refresh cached geometry ([Apple firstRect](https://developer.apple.com/documentation/appkit/nstextinputclient/firstrect%28forcharacterrange%3Aactualrange%3A%29), [coordinate invalidation](https://developer.apple.com/documentation/appkit/nstextinputcontext/invalidatecharactercoordinates%28%29)). |
| Explicit cancel | Use the OS input context's cancellation path only after a real-IME trace proves it does not convert/copy the candidate; restore frozen global selection and baseline host text. | Apple documents `discardMarkedText` as discarding the conversion session, with the client clearing its marked range; do not treat it as Save's commit path ([Apple discard](https://developer.apple.com/documentation/appkit/nstextinputcontext/discardmarkedtext%28%29)). |

Do not rebind text, call `setString:`, change first responder, or replace analysis styling while `hasMarkedText` is true. AppKit may deliver selection change before text change; a selection callback cannot by itself clear a global off-island selection or certify final text. The existing shell's deferred document/analysis mechanism is the migration precedent, but the island must tag every deferred action with generation/version/nonce so an old document's pending `SetDocument` cannot contaminate a new one. Synchronous Save/Open/Close settlement must read the final `NSTextView` text and verify `hasMarkedText == false` **before** I/O/swap; if it cannot, veto visibly. Moving the host may change IME context or candidate position even without rebinding; this remains a real-IME gate, not an assumption.

## Focus, geometry, and semantic updates

The host must be **visibly colocated** with the active canvas fragment and keep the OS's real keyboard focus. Make the host typography/background match the canvas over its occupied rectangle; mask the canvas text beneath it to avoid double rendering. Use the canvas hit-test for clicks elsewhere, then move the global caret and safely rebind/reposition the host. Do not toggle focus between a hidden input control and canvas on every key. During composition, the host stays bound to the same source window; scroll may move its HWND/NSView, but if the caret would leave the viewport, constrain that scroll or explicitly settle first. Test candidate-window tracking under Retina/high DPI, window movement, display switching and zoom. Offscreen canvas probes do not validate any of this.

For each semantic result, require `(document generation, snapshot version, policy identity, viewport range)` match before applying overlays. Rendering can clip tokens/diagnostics to the visible canvas, but it must not call RichEdit `EM_SETTEXTEX`, AppKit `setString:`, change host font metrics, or remove native marked styling mid-composition. The controller publishes an idle `Full` result only when `Complete`; a `Provisional` Full result retains the visible facts. This existing truthfulness rule must survive the island migration. Trace only event kind, state, version, bounded lengths, duration, and outcome—**no source text, candidate string or path**—and distinguish commit→presentation from actual physical paint.

Accessibility is a **separate release contract**: page-local RichEdit/NSTextView AX exposure does not make a canvas-backed file globally accessible. A full-document UIA/NSAccessibility provider must map source ranges independently and avoid duplicate speech from the focused island. Do not count the island as satisfying that contract merely because it accepts IME. Windows UIA `TextEditPattern` also models active composition/finalization, which is an additional integration test for the future provider, not a capability inherited automatically from the source model ([Microsoft TextEdit pattern](https://learn.microsoft.com/en-us/windows/win32/winauto/textedit-control-pattern)).

## Implementation slices and rollback criteria

| Slice | Smallest credible deliverable | Stop / rollback condition |
| --- | --- | --- |
| 1. Typed bridge and fake island | Add `CanvasCommittedEdit` with G/V/nonce, one controller apply path, version-checked echo suppression, off-island selection replacement, deterministic event-order permutation tests. Keep old shell default. | Any duplicate/stale event mutates engine, Cancel advances version, or global selection is truncated. |
| 2. Read-only canvas + visible host | Place a real RichEdit/NSTextView over a canvas caret; compare host/canvas glyph and caret rectangles on manageable Latin/CJK/bidi lines, high DPI and mixed CRLF. Keyboard focus remains native. | Candidate/caret geometry cannot be aligned without a full hidden mirror or native control recreations on each key. |
| 3. Opt-in editing and composition | `--canvas-experimental` routes ASCII/paste/selection then real IME through the bridge on both OSes, with synchronous Save/Open/Close settlement/veto and no stale analysis. | Real IME commit/cancel/reconversion duplicates text, loses candidate, changes source before commit, or corrupts Save. Default remains old page mode; do not silently fall back **mid-composition**. |
| 4. Whole-document UX/AX | Continuous scroll, offscreen selection and global AX provider pass on small and 100 MiB files. Compare old/new small-file command semantics and latency. | Screen reader sees only island or duplicate editor, selection/clipboard differs, or measured regression lacks a justified benefit. |
| 5. Default switch | Enable canvas path for all file sizes only after both OS acceptance matrices pass; retain temporary configuration/CLI rollback, never a new file format or sidecar. | Revert switch on target-OS regression while keeping engine files/undo semantics unchanged. |

The rollback unit is the **view/input adapter**, never document bytes. A faulted island may be destroyed/recreated only after composition has conclusively ended. If a command cannot settle safely, tell the user and keep the old document open; never save provisional text or discard an unsaved candidate to make the state machine simpler. Explicitly compare cold startup, p95 edit→draw submission, RSS, and current native page-mode correctness before switching defaults.

Report cold/warm and draw submission separately from physical presentation. |

The **next discriminating experiment** is a target-OS event/geometry probe, not a wholesale default switch: bind a visible 4-16 Ki host at one canvas caret, log privacy-safe begin/change/end ordering under a *real selected* IME, compare candidate rectangle and final projection with the existing page mode, and try Save/cancel while marked. If this fails, determine whether focus/geometry, context-window size, or event ordering is causal before adding TSF/NSTextInputClient machinery. Keep generated fixtures, traces and screenshots under repository `.temp/` or `.cache/`, and persist only durable conclusions in `docs/`.
