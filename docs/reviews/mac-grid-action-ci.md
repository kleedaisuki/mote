# Independent macOS Grid ShowMenu control CI integration review

Date: 2026-10-01. Scope: the uncommitted ShowMenu control and upload steps in `.github/workflows/ci.yml`, read together with `tests/MacGridAxActionContractProbe/{README.md,Run.ps1,Test-Guards.ps1,Contract.m}` and the existing [control review](mac-grid-action-contract-control-review.md). This review owns documentation only and was performed on Windows.

## Verdict

No substantive integration defect was found. The integration is suitable for collecting independent AppKit action-contract evidence on both native macOS runner architectures. It is non-gating diagnostic evidence, not a product accessibility acceptance gate. No native macOS build or GUI execution was performed locally.

## Verified integration contracts

- The native-AOT matrix maps `osx-x64` to `macos-15-intel` and `osx-arm64` to `macos-latest`. The control step selects only `osx-` RIDs; the owner additionally checks its actual process architecture before compiling or launching. Compilation uses the installed native Apple toolchain, not the mote executable or a cross-architecture assumption.
- All three pinned helper files match independently calculated SHA-256 hashes for both LF and CRLF representations. Exact pins are checked before portable preflight or native compilation. No unreviewed helper file is introduced by the workflow step.
- YAML parses successfully. The extracted `run` block, with the fixed matrix RID substituted, parses successfully with the PowerShell AST parser. It invokes portable guards in-process, then the actual owner through a separate `pwsh -NoProfile -File` process; the native owner's process exit is checked through `$LASTEXITCODE`.
- The step has a three-minute outer timeout and the driver a 45-second owned-process-tree watchdog, with cleanup in `finally`. The client's 20-second limit remains a cooperative phase/poll admission deadline, not a hard native-call cutoff. Compilation is bounded by the outer CI step, not the owner-process watchdog.
- The selected report is exactly `.cache/ci-inventory/mac-grid-action-contract-<rid>.json`. Native owner/client reports are exactly `.cache/mac-grid-action-contract/<rid>/server.json` and `client.json`. These three JSON paths are the uploaded artifact set; no executable, native stdout/stderr, desktop capture or source document is uploaded. Artifacts have separate RID names and 14-day retention.
- The helper is synthetic-only: no mote launch/link/patch, document input, global keyboard/mouse events, application activation request or TCC prompt/reset is added by the CI invocation. External AX discovery is scoped to the exact synthetic owner's PID. The native menu contains a fixed no-op item and uses owned tracking-mode cancellation.
- `control-completed` requires the seven observed variants and their advertised, opened-and-closed menu lifecycle, plus successful owner/child exits and normal owner shutdown. It intentionally does **not** require successful `actionError` values. Actual action errors and modern/legacy dispatch counters must be inspected independently; neither a zero driver exit nor this status means product AXShowMenu succeeds.
- `external-accessibility-unavailable` is permitted to exit zero only with untrusted external accessibility, clean owner/child exit and normal shutdown. It remains a distinct report status, not a fabricated native action pass. Portable preflight is also distinct and cannot supply native compilation, server/client or normal-exit evidence; the workflow does not pass `-ValidateOnly` to its actual native owner invocation.
- A failed control remains non-gating because its step uses `continue-on-error: true`. The upload uses `always()` on macOS and is itself non-gating, preserving available reports after diagnostic failure without converting them into strict acceptance. The existing strict test/build/publish checks are unchanged by these added steps. As written, the control's ordinary condition includes GitHub's default successful-prior-step admission; it need not run after an earlier gating failure, although the upload will still attempt available artifacts. A missing report produces a warning rather than an invented result.

## Reproducible validation and limits

A Python/PyYAML check parsed the workflow, selected the two new named steps, asserted their timeout/conditions/non-gating flags, and independently recomputed the three files' normalized LF and CRLF hashes against the embedded pins. It printed `yaml-and-dual-hashes-passed`. The extracted step was written only under `.cache/reviews/mac-grid-action-ci/step.ps1`; PowerShell AST parsing printed `workflow-powershell-parse-passed` with zero syntax errors.

The already completed portable guard execution documented in the control review was not repeated. This integration review does not certify Objective-C SDK compilation, AppKit/AX execution, accessibility trust, actual background menu behavior, target-host process cleanup, or a successful product action reply. The next useful evidence is the retained target-host report for each RID, including raw action errors and dispatch/lifecycle counters, not the enclosing green job color.
