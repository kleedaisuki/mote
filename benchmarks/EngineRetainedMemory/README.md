# Engine retained-memory controls

See [the investigation](../../docs/engine-retained-memory.md) for workload identity,
raw measurements, the inline async-completion root path, the failed staging-clear
candidate, and scope limits. This is a managed .NET 10 diagnostic, not an AOT
startup or input-latency benchmark.

Build from repository root into `.temp/EngineRetainedMemory/control-bin`, then run
`Run.ps1`. The exact 100 MiB LF fixture is generated by the JSON page benchmark and
lives under `.temp/JsonArrayPages/corpora`; results live under root `.cache`.
`inline` executes after OpenAsync without a new asynchronous boundary. `detached`
waits 100 ms outside timed intervals so its producer completion stack can unwind.
Each fresh process verifies 512 Undo and Redo steps and the exact final streaming
UTF-16 source hash. Full GC and reflection graph attribution are outside timings.

An optional `EngineProject` MSBuild property builds an archived Engine source;
an explicit edit count accepts 512 through 10400; `pause` enables heap diagnostics.
No benchmark memory result is a promise that the 32 MiB nominal edit budget is a
32 MiB unique physical allocation quota.
