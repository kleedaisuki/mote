# Native JSON open attribution (Windows x64, Native AOT)

This is an isolated **diagnostic benchmark**, not a product change or a latency
gate. It recreates the current Engine in repository `.temp`, with a different
namespace and fixed phase timers, while retaining a direct reference to the real
unmodified Engine as its baseline. Preparation fails if a reviewed source shape
changes. No copied Engine source is checked into this directory. Preparation requires an
empty scratch directory and never deletes an old binary. A unique preparation
fingerprint is embedded in the compiled probe; the runner verifies it before
correctness/generation and in every accepted row, together with current Engine,
template and generated-source hashes. This rejects accidental stale builds,
not malicious binary substitution or a signed provenance attack.

## Run from the repository root

```powershell
python -B benchmarks/NativeJsonOpenAttribution/prepare.py
dotnet publish .temp/native-json-open-attribution/Probe.csproj `
  -c Release -r win-x64 -p:PublishAot=true `
  -o .temp/native-json-open-attribution/publish
python -B benchmarks/NativeJsonOpenAttribution/run.py --suite attribution
# Separate counterexample suites; do not treat either candidate as an accepted optimization.
python -B benchmarks/NativeJsonOpenAttribution/run.py --suite broad
python -B benchmarks/NativeJsonOpenAttribution/run.py --suite hybrid
# Minimal direct-return candidate; eligible for integration experiment, not product acceptance.
python -B benchmarks/NativeJsonOpenAttribution/run.py --suite direct
```

.NET 10 and the Windows Native AOT native build toolchain are required. The
runner intentionally accepts the Windows x64 `Probe.exe`; this does not claim
macOS/ARM64 evidence. A new clean artifact directory can be selected with
`--directory .temp/<name>` on both scripts, and publish to its `publish` child.
`--output .cache/<name>` selects results. Linked or outside-repository artifact
paths fail closed. Existing suite rows are never overwritten; choose a new
`--output` for a repeated cohort. Engine source changed after preparation also
fails closed, requiring a fresh preparation/publish. `--repeats` defaults to six and accepts 1–20. Each suite is an
independent experiment; rerun only the suite needed for a new source/binary or
an unresolved question. Every invocation performs its own differential oracle,
with a 180-second bound; each measured child has a 30-second bound.

Portable protocol checks and content-free result summaries are also available:

```powershell
python -B benchmarks/NativeJsonOpenAttribution/test_protocol.py
python -B benchmarks/NativeJsonOpenAttribution/summarize.py `
  .cache/native-json-open-attribution/reproduced/hybrid-rows.jsonl
```

The ASCII JSON fixture is generated by the existing ordinary Native JSON pilot
corpus preparation. `attribution` measures 1 and 100 MiB; `broad`, `hybrid` and `direct`
measure 100 MiB JSON plus 10 MiB dense LF, dense CRLF, dense CR and no-newline
files. Generation, a streaming SHA scan and the independent byte-line oracle
precede timing. **The OS file cache is not evicted.** Each observation is a fresh
child process; mode order rotates by repetition rather than running all baseline
observations first. The 100 MiB JSON length/line oracle is 104,857,600 UTF-16
units and 2,097,152 lines. No semantic parse, editor, Save or automation is run.

## Controls, rejected candidates and direct-return discriminator

| Mode | Meaning |
| --- | --- |
| `baseline` | Real unchanged `Mote.Engine.Document.OpenAsync` |
| `copy-control` | Namespace-isolated Engine copy, phase timers disabled; same source scaffolding/candidate branches as the timed copy |
| `phases` | Copied current algorithm with five fixed sequential phase timers |
| `line-prototype` | **Rejected:** count LF, then search every CR excluding CRLF; substantially regresses dense CR/CRLF |
| `line-hybrid` | **Rejected:** use candidate only in no-CR leaves, otherwise original scalar counting; regresses dense LF |
| `line-direct` | Minimal candidate: no-CR spans return CountLF directly; other spans retain the original scalar algorithm |
| `line-check` | Differential scalar/candidate snapshot line/offset oracle; not a timed Open sample |

`PhaseMs` / `PhaseCalls` index order is **read-await, hash, decode, string-chunk
creation, rope construction**. The terminal EOF read is included; a 100 MiB
ASCII file with full 64 KiB reads has counts `[1601,1600,1600,1600,1]`.
The phase timers include stopwatch calls, waits, scheduling and GC within their
scopes. They are wall time, not a CPU sample profiler. Phase totals do not include
all setup/teardown, EOF decode or metadata checks; report the residual, do not
silently normalize it away.

`OpenMs` includes whole Engine open and tiny immediately following snapshot
length/line reads. `AllocatedBytes` uses process-wide precise cumulative managed
allocation deltas, because asynchronous continuations can migrate threads. It
is not retained memory or a per-phase allocation breakdown. `Collections` are
whole-open generation counts. `CpuMs` is a coarse process CPU counter and can be
zero for a short operation; it can exceed wall time because other process
threads participate. After a yield, `WorkingSetBytes` is a point-in-time process
working set; `PeakWorkingSetBytes` is the process counter read at that point,
not a GUI memory peak. `PostYieldLiveBytes` is a forced-GC live-heap observation
outside the measured Open; yielding encourages producer unwind, but is not a
formal producer-lifetime barrier. `LengthUtf16` and `LineCount` must equal the
independent ASCII byte oracle. `LineOracleChecked` marks that validation.

Every suite records source/template/binary SHA identities, source commit,
fixture identities, individual rows, runtime, OS, architecture and processor
count. Do not compare binaries from different cohorts as an isolated speedup;
use matched observations within one cohort. Six local processes are not a
reliable p95 or a heterogeneous-runner confidence interval. No measurement here
claims physical keyboard latency, source draw, compositor presentation or disk
cold-start latency. The current findings and measured counterexamples are in
[`docs/performance/native-json-open-attribution.md`](../../docs/performance/native-json-open-attribution.md).
